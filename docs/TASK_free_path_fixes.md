# ТЗ: бесплатный путь — выравнивание карточек и возврат к расчёту

Две находки боевой проверки 24.09.2026 после деплоя `tier_naming`. Обе про
бесплатную часть сайта, к движку расчёта отношения не имеют.

## Часть 1. Цены в блоке «Категории» стоят на разной высоте

### Проблема

После перехода на пять карточек с двойными названиями сломалось выравнивание.

- Название занимает одну или две строки в зависимости от уровня: «Премиум» в
  одну, «Старт · Косметический», «Эконом · Капитальный» и «Бизнес ·
  Евроремонт+» в две. Блок текста прижат к низу карточки, поэтому строка цены на
  каждой карточке начинается на своей высоте.
- На «Бизнес» и «Премиум» единица `тыс ₽/м²` оторвалась от числа и перенеслась
  на следующую строку: «100–150 тыс» / «₽/м²».

Файл `src/pages/HomePage.jsx`, `PricingSection`.

### Что сделать

Способ на усмотрение исполнителя. Требования к результату:

1. На всех пяти карточках строка цены начинается на одной высоте.
2. Единица измерения не отрывается от числа.
3. Работает на 1440, 1024 и в мобильном виде.

Разумные варианты: фиксированная минимальная высота блока названия под две
строки, либо выравнивание содержимого карточек по общей сетке. Уменьшать шрифт
названия до неразборчивого нельзя.

## Часть 2. «Быстрый расчёт — бесплатно» уводит в начало вместо результата

### Проблема

`src/pages/B2CDetailPage.jsx`, строка 227. Под текстом «Хотите узнать примерный
бюджет прямо сейчас?» стоит кнопка «Быстрый расчёт — бесплатно», которая делает
`navigate('/b2c')`. А `/b2c` всегда открывается экраном выбора режима, потому что
`showMode` стартует как `true` (`B2CQuizPage.jsx`, строка 50).

Человек нажимает кнопку, обещающую бюджет прямо сейчас, и получает вопрос «Какой
расчёт вам нужен?» — то есть его спрашивают ровно про то, на что он только что
ответил кнопкой. Дальше два пути, и оба плохи: выбрать «Быстрый расчёт» и заново
пройти девять шагов, или выбрать «Детальная смета» и вернуться на тот же пейволл,
с которого пришёл.

**Уже посчитанная вилка при этом никуда не делась.** Она лежит в
`sessionStorage` под ключом `rpkm-last-b2c`, и страница `/b2c-result` показала бы
её мгновенно. Кнопка про неё не знает.

Найдено Дмитрием на боевом 24.09.2026.

### Решение Дмитрия от 24.09.2026

Если расчёт уже есть — показать его. Если нет — в квиз, минуя экран выбора
режима.

### 2.1. Кнопка на пейволле

`src/pages/B2CDetailPage.jsx`, строка 227.

```js
onClick={() => {
  let hasQuick = false;
  try {
    const raw = sessionStorage.getItem('rpkm-last-b2c');
    hasQuick = !!(raw && JSON.parse(raw)?.result);
  } catch { hasQuick = false; }
  navigate(hasQuick ? '/b2c-result' : `/b2c?mode=quick&tier=${tier}`);
}}
```

Проверять именно разбираемость и наличие `result`, а не просто присутствие ключа:
в хранилище может лежать мусор, и тогда `/b2c-result` покажет «Расчёт не найден»,
то есть тот же тупик другими словами.

`tier` берётся из состояния страницы. К моменту отрисовки пейволла эффект сида
уже отработал, поэтому если человек пришёл из квиза, уровень сохранится. Если
пришёл напрямую, там дефолт `capital` — это текущее поведение, не ухудшение.

### 2.2. Квиз умеет пропускать экран выбора режима

`src/pages/B2CQuizPage.jsx`, строка 50.

```js
const [showMode, setShowMode] = useState(searchParams.get('mode') !== 'quick');
```

Объявление `searchParams` сейчас идёт ниже `showMode` — порядок придётся
поменять. Никакой другой параметр поведение не меняет: `mode` со значением,
отличным от `quick`, и его отсутствие оставляют экран выбора на месте.

### 2.3. На странице результата нужен выход к новому расчёту

Предложение исполнителя ТЗ, Дмитрий не просил — сказать прямо в отчёте, если
решит убрать.

`src/pages/B2CResultPage.jsx` сейчас предлагает только «Печать сметы» и «Открыть
детальную смету». Начать новый расчёт можно лишь через пункт «Калькулятор» в
шапке. После правки 2.1 на эту страницу будет приходить человек, которому,
возможно, нужен как раз новый расчёт с другими вводными.

Добавить рядом с «Открыть детальную смету» кнопку «Посчитать заново», ведущую на
`/b2c?mode=quick`.

## Не трогать

- Движок расчёта и контрольные цифры.
- Экран выбора режима сам по себе: он остаётся для тех, кто пришёл на `/b2c` без
  параметра.
- Кнопки «Попробовать 14 дней бесплатно» и «Войти как Профи» на пейволле.
- Ключ `rpkm-last-b2c-detail` и сид детальной формы.

## Критерии приёмки

1. Блок «Категории»: на пяти карточках строка цены на одной высоте, единица не
   отрывается от числа. Проверено на 1440, 1024 и в мобильном виде.
2. Пройти быстрый квиз до результата, оттуда «Открыть детальную смету», попасть
   на пейволл, нажать «Быстрый расчёт — бесплатно» → сразу страница результата с
   прежней вилкой, без повторного прохождения квиза.
3. В чистой вкладке открыть `/b2c-detail` без подписки, нажать «Быстрый расчёт —
   бесплатно» → квиз с первого шага, без экрана «Какой расчёт вам нужен?».
4. Положить в `sessionStorage` под ключом `rpkm-last-b2c` строку `{` и нажать ту
   же кнопку → квиз с первого шага, а не страница «Расчёт не найден».
5. Открыть `/b2c` без параметров → экран выбора режима на месте.
6. На странице результата есть «Посчитать заново», ведущая в квиз с первого шага.
7. Контрольные цифры детальной сметы не сдвинулись: `cosmetic` 1 341 074 ₽,
   `capital` 3 758 823 ₽, `euro` 4 791 147 ₽, `euro_top` 7 433 602 ₽, `premium`
   40 770 069 ₽.
8. `npx vite build` проходит без ошибок.
9. Отчёт `docs/REPORT_free_path_fixes.md` написан по фактическим результатам.

## Порядок работ

1. Часть 1 — вёрстка, отдельный коммит.
2. Часть 2 целиком — один коммит, три файла связаны между собой.

Всё проверяется локально в браузере: главная, квиз и страница результата открыты
всем. Пейволл на `/b2c-detail` виден без подписки, а сама детальная форма за ним
в этом ТЗ не участвует.
