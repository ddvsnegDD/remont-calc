# Отчёт: мелочи на /club и /pro (m_club_pro_polish, m_verify_sub_shape)

**Коммит:** `35c70fa` (без push).

## Что изменено

### Часть 1. verify отдаёт то же, что /me

- [`server.js`](../server.js): новая `formatSubscription(sub)` рядом с `formatQueue` →
  `{ plan, status, expiresAt, tier }` или `null`. Используется в `/api/auth/me`, `/api/subscription/status`,
  `/api/auth/verify` и `/api/subscription/trial` (там `subscription` теперь тоже с `tier`).
  `/api/auth/verify` дополнительно считает `hasUsedTrial` и отдаёт `trialUsed`. Остальные ответы (в т.ч.
  админский `subscription: sub` и `/api/payments/:id`) не менялись.
- [`src/lib/auth.jsx`](../src/lib/auth.jsx), `verify`: после `setQueue` добавлено `setTrialUsed(!!data.trialUsed)`.
- Потребители ответа verify: `LoginModal.jsx:65`, `LoginChoicePage.jsx:62`, `B2BLoginPage.jsx:83,85` только
  вызывают `verify(...)` и результат не читают; поиск по `src/` `expires_at|started_at` пуст. Читать нечего,
  править не пришлось.

### Часть 2. Ответы на /pro рядом с кнопкой

[`src/pages/ProPage.jsx`](../src/pages/ProPage.jsx): `notice` — объект `{ place, kind, text }`, `renderNotice(place)`
выводит сообщение под своей кнопкой с рамкой как на /club. Места: `hero` (шапка), `compare` (блок сравнения),
`whitelabel` и `csv` (карточки PRO-кабинета). Тост внизу страницы убран. Ошибка не исчезает сама; успех триала
снимается через 8 с. `handleTrial(place)` и `handlePay(place)` принимают место, перед запуском очищают прежнее
сообщение; ошибки оплаты (`payments_off`, `provider`, сеть) идут тем же путём.

**Отступление от ТЗ:** сообщения «White-label PDF — скоро» и «Экспорт CSV — скоро» тоже шли через этот `notice`
(тост). Чтобы убрать тост целиком, они выведены под своими кнопками с видом `info` (серая рамка, без отметки) и
снимаются через 4 с. Других изменений в них нет.

### Часть 3. Неразрывный пробел перед «г.»

`fmtDate` в `ClubPage.jsx`, `ProPage.jsx`, `PaymentReturnPage.jsx` заменяет пробел перед конечным «г.» на
`U+00A0` (`.replace(/\s+г\.$/, ' г.')`). Остальные места с датами не менялись.

## Проверка

- `node --check server.js` и `npx vite build` — без ошибок.
- `formatSubscription` (код взят из `server.js`, проверка узлом): строка БД → `{"plan":"pro_trial","status":"trial",
  "expiresAt":"2026-10-10T10:00:00.000Z","tier":"pro"}`, `null` → `null`, сырых `expires_at`/`started_at` в ответе
  нет.
- Реальные страницы в браузере на 390 px, API — заглушка:
  - `/club` с очередью (месяц + год): во всех четырёх датах «г.» стоит на одной строке с годом (замерено
    `Range`-прямоугольниками), `scrollWidth === 390`;
  - `/pro`: отказ триала из шапки → сообщение внутри шапки; оплата из шапки (`payments_off`) → заменяет его, тоже в
    шапке; отказ триала из блока сравнения → сообщение под этой кнопкой, шапка очищена; сообщение осталось через
    5 с (раньше пропадало через 4); тоста внизу нет; переполнения нет.

## Не проверено

- Путь `verify` → `trialUsed` в контексте и плашка «Триал активен до …» сразу после входа — только чтением кода и
  проверкой формата ответа: реальный вход по коду без базы не воспроизвести. Критерии 1–3 из ТЗ проверяются после
  деплоя на ddv681121.
- Успешное сообщение триала на /pro (8 с) отдельно по времени не замерялось.
