# ТЗ: уровни детальной сметы — состав вместо коэффициентов

## Проблема

Детальная смета (`SpecCalc.compute`, `src/lib/spec-calculator.js`) даёт для квартиры
60 м², новостройка-монолит, без отделки, полный цикл:

> **Поправка от 23.09.2026, важнее всего остального в этом документе.**
> Проценты ниже по тексту считались от вилки квиза, полученной на неизвестном
> наборе ответов, и оказались завышены примерно на десять пунктов. Вилка квиза
> не константа: `TIERS` для капитального это 35 000 — 55 000 ₽/м², а дальше на
> них накручиваются модификаторы (тип дома, коммуникации, дизайн-проект, сроки,
> отделка от застройщика), плюс стоимость окон добавляется отдельной суммой.
> Разные правдоподобные наборы ответов дают верх вилки от 59 до 70 тысяч ₽/м².
>
> **Эталонный случай, утверждён Дмитрием 23.09.2026.** Все сравнения вилки и
> детальной сметы — только на нём, и в отчётах он выписывается явно:
> новостройка-монолит (`house_type: 'nov_monolith'`), без отделки от застройщика
> (`finish_type: 'no_finish'`), 60 м², 1 санузел, 3 окна, 2 комнаты, коммуникации
> полные (`comms: 'full'`), дизайн-проекта нет (`design: 'no'`), сроки не срочные
> (`timing: 'flexible'`), перепланировки нет, режим `full`.

| | ₽/м² |
|---|---|
| Квиз `capital` на эталонном случае | 41 638 — 65 431 |
| Детальная `capital` до переделки | 82 550 |

Превышение верха вилки — **+26 %**. Цель была «10–15 % сверху», но на верной
основе она потеряла смысл: смета, лежащая внутри рыночной вилки, лучше, чем
смета выше неё. Фактическая цель — привести капитальный в вилку, не занижая
расценки.

Причина не в ценах позиций: расценки взяты из реальных тендерных смет и верны.
Причина в **составе**. `SPEC_DATA.full` — это один конкретный объект (евроремонт),
где все 180 м² стен обшиты ГКЛ по каркасу в два слоя и дополнительно утеплены,
а потолок — подвесной ГКЛ. `TIER_MULTIPLIERS` при этом трогает только `finish` и
`sanitary`, а 41 % денег лежит в `rough`:

| класс | ₽ | доля |
|---|---|---|
| rough (конструктив) | 2 034 890 | 41,1 % |
| finish | 998 807 | 20,2 % |
| prep (подготовка) | 693 183 | 14,0 % |
| doors | 456 527 | 9,2 % |
| terminal (оконечка) | 315 198 | 6,4 % |
| windows | 180 336 | 3,6 % |
| engineering (магистрали) | 174 049 | 3,5 % |
| sanitary (магистрали) | 100 000 | 2,0 % |

**Доказательство, что одними коэффициентами задача не решается.** Понижающие
на `prep`, материалы `finish` и материалы `terminal` — даже жёсткие — дают:

| коэффициенты | результат | к верху вилки |
|---|---|---|
| prep 0,85 / finish mp 0,80 / term mp 0,70 | 79 387 ₽/м² | +33 % |
| prep 0,75 / finish mp 0,65 / term mp 0,55 | 77 322 ₽/м² | +30 % |
| prep 0,65 / finish mp 0,50 / term mp 0,45 | 75 365 ₽/м² | +27 % |

Ниже +27 % коэффициенты не опускают, потому что деньги не там. А чтобы
опустить сильнее, пришлось бы занижать сами расценки — то есть врать в цифре,
которую пользователь потом понесёт подрядчику.

**Что решает.** Смена состава `rough` для уровня «Капитальный»:

| вариант | результат | к верху вилки |
|---|---|---|
| только убрать утепление стен | 76 246 ₽/м² | +28 % |
| ГКЛ стен → штукатурка, утепление оставить | 73 822 ₽/м² | +24 % |
| **ГКЛ стен → штукатурка + убрать утепление** | **67 518 ₽/м²** | **+3,2 %** |
| то же + потолок без ГКЛ | 62 797 ₽/м² | +6 % |

Третий вариант попадает в целевой коридор при коэффициентах = 1. То есть
коэффициенты из этого ТЗ становятся точной подстройкой, а не основным рычагом.

---

## Решение по составу (подтверждено Дмитрием 23.09.2026)

> Для уровня «Капитальный» в жилых помещениях стены **штукатурятся по маякам**
> (расценка берётся из существующей позиции «Штукатурка стен толщиной до 20 мм
> по сетке», 2 486 ₽/м² работа+материал), а не обшиваются ГКЛ по каркасу;
> **утепление стен не выполняется**; потолок остаётся подвесным ГКЛ.

Подтверждено. Расценку штукатурки брать из существующей позиции, новых цифр
не придумывать.

## Часть 2. Переименование уровней

Текущий набор `SPEC_DATA.full` — это **евроремонт**, а не капитальный. Сейчас он
подписан как `capital` с множителями 1,0, а `euro` получает надбавку сверху.
Это перевёрнуто.

Целевая модель:

| tier | набор позиций | множители |
|---|---|---|
| `cosmetic` | **новый набор** (часть 4) | все 1,0 |
| `capital` | `full` со сменой состава (часть 3) + понижающие | часть 3 |
| `euro` | `full` как есть | все 1,0 |
| `premium` | `SPEC_DATA.premium` как есть | без изменений |

`TIER_LABELS` дополнить: `cosmetic: 'Косметический'`.

**Обратная совместимость.** `tierKey` в `SpecCalc.compute` сейчас падает на
`'capital'` при неизвестном уровне — оставить. Квиз (`B2CQuizPage.jsx`) мапит
`repair_type` через `tierMap`, где `cosmetic → capital`; после этого ТЗ маппинг
должен стать прямым: `cosmetic → cosmetic`.

## Часть 3. Уровень «Капитальный»

Строится из того же `SPEC_DATA.full` двумя механизмами.

### 3.1. Смена состава

Нужен механизм подмены позиций по уровню. Предлагаемая форма — отдельный
экспорт в `src/lib/spec-data.js`, чтобы не дублировать массив позиций:

```js
export const TIER_COMPOSITION = {
  capital: {
    // позиции, исключаемые из набора (сверка по name + unit)
    exclude: [
      { name: 'Облицовка стен из гипсокартона/фанеры в два слоя по металлическому каркасу', unit: 'м2' },
      { name: 'Устройство утепления стен', unit: 'м2' },
    ],
    // позиции, добавляемые взамен
    add: [
      { g:'05.05.02.06', sub:'05.05.02.06.02', name:'Штукатурка стен толщиной до 20 мм по сетке',
        mat:'Штукатурная смесь, сетка, маяки', unit:'м2', vol:'area*3', wp:<из поз.43>, mp:<из поз.43>, cls:'rough' },
    ],
  },
};
```

`wp`/`mp` для добавляемой позиции **взять ровно из существующей поз. 43**
(штукатурка в санузле) — не придумывать новые цифры. `vol` — та же формула,
что у исключаемой облицовки ГКЛ (сверить по факту в данных, ожидается `area*3`).

В `SpecCalc.compute` применять `TIER_COMPOSITION[tierKey]` к `items` до цикла
расчёта. Для уровней без записи в `TIER_COMPOSITION` набор не меняется.

### 3.2. Понижающие коэффициенты

**Решение Дмитрия от 23.09.2026, принято по прогону вариантов — мягкий вариант:**

```js
capital: {
  rough:       { wp: 1.00, mp: 1.00 },
  prep:        { wp: 0.90, mp: 0.90 },   // 1 слой шпатлёвки вместо 2, без стеклохолста
  finish:      { wp: 1.00, mp: 0.85 },   // финишный материал дешевле
  terminal:    { wp: 1.00, mp: 0.80 },   // оконечка эконом-сегмента
  engineering: { wp: 1.00, mp: 1.00 },
  sanitary:    { wp: 1.00, mp: 1.00 },
  doors:       { wp: 1.00, mp: 1.00 },
  windows:     { wp: 1.00, mp: 1.00 },
}
```

Результат: **65 344 ₽/м²**, то есть **−0,1 % к верху вилки квиза** на эталонном
случае (верх вилки 65 431 ₽/м²). Капитальный оказывается внутри рыночной вилки,
у самой её верхней границы.

**Контекст решения, чтобы его потом не переигрывали вслепую.** Смена состава
(часть 3.1) сама по себе дала 67 518 ₽/м², то есть +3,2 % к верху вилки, то есть
почти привела капитальный в вилку без единого коэффициента. Поэтому эти множители не служат
попаданию в цифру: они выражают то, что на капитальном ремонте финишный материал
и оконечка действительно дешевле, чем на евроремонте. Прогонялись варианты
мягкий (65 344 ₽/м²), средний (64 160) и жёсткий (62 976). Выбран мягкий —
решение Дмитрия от 23.09.2026, подтверждено повторно после пересчёта на
эталонном случае: множители обоснованы тем, что финишный материал и оконечка на
капитальном действительно дешевле, чем на евроремонте, и это не зависит от того,
какой знаменатель мы берём для процентов.

Для `euro` все восемь классов = 1,00 (текущие надбавки 1,30/2,00 снимаются —
теперь `full` и есть евроремонт).

## Часть 4. Уровень «Косметический» — новый набор позиций

Расценки и состав получены от Дмитрия 23–24.09.2026, все решения ниже — его.

### Что делаем

Косметический ремонт — обновление без вскрытия конструкций: заделка трещин,
шпатлёвка в один слой, покраска, замена финишного покрытия пола и части
оконечки. Двери, окна, плитка на стенах санузла, конструктив и магистрали
не трогаются.

Своего набора позиций у уровня сейчас нет: `tierMap` схлопывает `cosmetic`
в `capital`, и человек, выбравший косметический, получает капитальный.

### 4.2. Откуда взялись новые расценки

В комментарии над массивом зафиксировать происхождение, иначе через месяц
никто не восстановит:

- Заделка трещин 1500 + 200 ₽/пог.м, объём 0,2 пог.м на м² стен под покраску.
- Демонтаж покрытия пола 350 ₽/м² (ламинат) — только работа. Паркет стоил бы
  800, но для косметики принят ламинат как типовое покрытие вторички.
- Демонтаж плитки 1000 ₽/м² — только работа, только пол санузла.
- Выравнивающая стяжка 10 мм: 900 работа + 350 материал.
- Шпатлёвка в один слой — **ровно половина двухслойной расценки той же
  поверхности**: стены 1497,38 / 92,24 → 748,69 / 46,12; потолки
  1537,86 / 92,24 → 768,93 / 46,12. Если двухслойные расценки когда-нибудь
  пересматриваются, однослойные пересчитываются от них, а не правятся отдельно.

### 4.3. Движок и интерфейс

- `SpecCalc.compute`: при `tier === 'cosmetic'` набор — `SPEC_DATA.cosmetic`,
  независимо от `mode`. WhiteBox для косметики смысла не имеет: застройщик
  сделал стяжку и штукатурку, а мы обновляем старую квартиру.
- `TIER_MULTIPLIERS.cosmetic` — все восемь классов по 1,0. Набор уже собран
  под уровень, множители ему не нужны.
- `TIER_LABELS.cosmetic` — уже есть, не трогать.
- `src/data/specTier.js`: `tierMap.cosmetic` меняется с `'capital'` на
  `'cosmetic'`. Это тот самый отложенный пункт, теперь ему есть куда вести.
- `src/pages/B2CDetailPage.jsx`, массив карточек выбора уровня (сейчас три

## Часть 5. Объём перегородок зависит от перепланировки

Решение Дмитрия от 23.09.2026, найдено при боевой проверке.

### Проблема

Позиция «Устройство перегородок из листовых материалов с обшивкой с двух сторон
в два слоя по металлическому каркасу с утеплением» имеет объём `area*0.5` —
половину площади квартиры в квадратных метрах перегородки, независимо от ответа
про перепланировку. На 60 м² это 30 м² и 161 844 ₽, на 150 м² будет 75 м².

Человек, выбравший «перепланировка не требуется», платит за возведение новых
перегородок ровно столько же, сколько выбравший полную перепланировку со сносом
и согласованием в МЖИ. Ответ на вопрос квиза на цифру не влияет.

Та же позиция с той же формулой есть в `SPEC_ITEMS_WHITEBOX`. В премиальном
наборе своя пара: «Монтаж перегородок из ПГП Knauf 100мм» (`area*0.8`) и
«Монтаж перегородок ГКЛ в 2 слоя с623» (`area*0.15`), обе тоже ни от чего
не зависят.

### Техническое ограничение

`evalVolume` в `src/lib/spec-calculator.js` передаёт формулам объёма только
четыре переменные: `area`, `sanitary`, `windows`, `rooms` (якорь — строка
`new Function('area', 'sanitary', 'windows', 'rooms', 'Math', ...)`). Ответа про
перепланировку среди них нет, его нужно добавить. Это правка расчётного ядра,
поэтому часть оформлена отдельно, а не «заодно».

### Что сделать

**5.1. Коэффициент перегородок по уровню перепланировки.**

Добавить в `src/data/replan.js` рядом с `REPLAN_SURCHARGE` — это его естественный
дом, файл уже общий для обоих движков:

```js
// Доля от базового объёма перегородок. При «не требуется» перегородки не
// возводятся вовсе, и позиция выпадает из сметы (SpecCalc пропускает строки
// с нулевым объёмом).
export const REPLAN_PARTITION_FACTOR = {
  no:    0,
  light: 0.5,
  full:  1.0,
};
```

Второго экземпляра этих чисел быть не должно — та же причина, что с
`REPLAN_SURCHARGE`.

**5.2. Переменная в контексте формул.**

`src/lib/spec-calculator.js`: передать в `evalVolume` пятую переменную
`replanFactor` со значением `REPLAN_PARTITION_FACTOR[replanKey]`. `replanKey`
в `SpecCalc.compute` уже вычислен и провалидирован, брать его.

Порядок аргументов в `new Function` и в вызове должен совпадать — это частая
ошибка, проверить отдельно.

**5.3. Формулы объёма.**

| набор | позиция | было | стало |
|---|---|---|---|
| `SPEC_ITEMS_FULL` | Устройство перегородок из листовых материалов… | `area*0.5` | `area*0.5*replanFactor` |
| `SPEC_ITEMS_WHITEBOX` | та же позиция | `area*0.5` | `area*0.5*replanFactor` |
| премиум | Монтаж перегородок из ПГП Knauf 100мм | `area*0.8` | `area*0.8*replanFactor` |
| премиум | Монтаж перегородок ГКЛ в 2 слоя с623 | `area*0.15` | `area*0.15*replanFactor` |

Пропорции между ПГП и ГКЛ в премиуме не менять.

### Не трогать

- «Устройство стеклянных перегородок» (`sanitary*1.95`) и «Монтаж стеклянной
  душевой перегородки премиум» (`sanitary*4.5`) — это душевые ограждения,
  к перепланировке отношения не имеют.
- «Штукатурка стен и перегородок Ротбанд» в премиуме (`area*3.5`) — это отделка
  поверхностей, а не возведение перегородок.
- Надбавку за перепланировку (`REPLAN_SURCHARGE`) и порядок её начисления.
- Расценки `wp`/`mp` всех позиций.

### Критерии приёмки

Эталонный случай, 60 м² / 1 санузел / 3 окна / 2 комнаты, `mode: 'full'`:

1. Капитальный, `replan: 'no'` → **3 758 823 ₽ (62 647 ₽/м²)**, позиции
   с перегородками в смете нет вовсе.
2. Капитальный, `replan: 'light'` → **3 919 745 ₽ (65 329 ₽/м²)**, перегородки
   15 м² на 80 922 ₽.
3. Капитальный, `replan: 'full'` → **4 241 700 ₽ (70 695 ₽/м²)**, перегородки
   30 м² на 161 844 ₽ — то есть не изменился относительно текущего поведения.
4. Евроремонт, `replan: 'no'` → **4 791 147 ₽ (79 852 ₽/м²)**.

7. `npx vite build` проходит без ошибок.
