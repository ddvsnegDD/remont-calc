# ТЗ: единые названия уровней и контекст в квизе

Найдено 24.09.2026 при боевой проверке частей 8 и 9 `spec_tiers`. К движку
расчёта отношения не имеет: цифры верные, а слова вокруг них расходятся.

## Проблема

### 1. Уровни называются тремя разными наборами слов

| где | что видит человек |
|---|---|
| Главная, блок «Категории» | Эконом · Комфорт · Бизнес · Премиум |
| Результат квиза, «Категория» | Капитальный стандарт · Евроремонт · Премиум |
| Детальная форма, карточки | Косметический · Капитальный · Евроремонт · Премиум |
| Печатная смета, «Категория» | то же, что на детальной форме |

Человек кликает «Комфорт», проходит квиз и получает «Евроремонт». Связи между
двумя словами на сайте нет нигде. Дмитрий на боевой проверке сформулировал это
так: «Если комфорт и евроремонт это одно и то же, то тогда да».

### 2. Карточка «Бизнес» обещает не то, что считает

`src/pages/HomePage.jsx`, строка 194: карточка показывает **100–150 тыс ₽/м²**, а
ведёт на `tier: "euro"`, который в `TIERS` (`src/lib/calculator.js:8`) равен
**60 000–85 000 ₽/м²**. Человек получает вилку примерно на сорок процентов ниже
обещанной.

Уровень с ровно такими цифрами в коде есть: `euro_top`, «Евроремонт+»,
100 000–150 000 ₽/м² (`calculator.js:9`). Карточка должна вести на него.

Это конкретная причина давно числящегося долга «`euro_top` и `luxury` через квиз
недостижимы».

### 3. Карточка «Премиум» тоже расходится с расчётом

Карточка обещает «200+ тыс ₽/м²», `TIERS.premium` — 160 000–220 000 ₽/м².

### 4. Косметический уровень недостижим из квиза

Карточек на главной четыре, косметической среди них нет. Попасть в уровень можно
только дописав `?tier=cosmetic` в адрес руками. Уровень на 23 позиции сделан в
части 4 `spec_tiers`, а посетитель выбрать его в бесплатном расчёте не может.

Отдельно: белый список в `B2CQuizPage.jsx:53` — `['cosmetic','capital','euro','premium']`.
`euro_top` в нём нет, то есть даже руками написанный `?tier=euro_top` молча
свалится в `capital`.

### 5. Выбранная категория не видна нигде внутри квиза

Человек выбирает категорию на главной, дальше проходит девять шагов и ни на одном
не видит, что он выбрал. Проверить себя до самого конца невозможно. На боевой
проверке это привело к тому, что владелец сайта сам не смог вспомнить, с какой
карточки начинал прогон, и мы потратили на выяснение два захода.

## Решения Дмитрия от 24.09.2026

1. **Названия двойные**: «Комфорт · Евроремонт». Маркетинговое слово ведёт,
   инженерное уточняет.
2. **В квизе показывать категорию и все уже данные ответы** компактной строкой.
3. **Карточка «Бизнес» ведёт на `euro_top`.**
4. **Косметический добавляется пятой карточкой** на главную.
5. **Детальная смета для «Бизнеса» считается как «Бизнес»**, а не сваливается в
   «Комфорт». Множители: материалы ×2,4, работы ×1,15 (часть 5).

## Часть 1. Единый источник названий

**Что сделать.** Завести `src/data/tierNames.js` — одно место, где уровень
связывается со всеми своими именами и ценой на витрине.

```js
// Единственный источник названий уровня. Маркетинговое имя ведёт на витрине,
// инженерное уточняет состав работ. Совпадают — показываем одно.
// Цены берутся отсюда же, чтобы карточка на главной не могла разойтись с TIERS.
export const TIER_NAMES = {
  cosmetic: { marketing: 'Старт',   engineering: 'Косметический',  low:  20000, high:  30000 },
  capital:  { marketing: 'Эконом',  engineering: 'Капитальный',    low:  35000, high:  55000 },
  euro:     { marketing: 'Комфорт', engineering: 'Евроремонт',     low:  60000, high:  85000 },
  euro_top: { marketing: 'Бизнес',  engineering: 'Евроремонт+',    low: 100000, high: 150000 },
  premium:  { marketing: 'Премиум', engineering: 'Премиум',        low: 160000, high: 220000 },
};

// «Комфорт · Евроремонт», но для премиума просто «Премиум».
export function tierTitle(key) {
  const t = TIER_NAMES[key];
  if (!t) return '';
  return t.marketing === t.engineering ? t.marketing : `${t.marketing} · ${t.engineering}`;
}
```

**Слово «Старт» под вопросом.** Это моё предложение под лестницу
Старт–Эконом–Комфорт–Бизнес–Премиум. Дмитрий, если не нравится, назови сам, и
исполнитель подставит. Менять только `marketing` в одной строке.

**Цены `low`/`high` обязаны совпадать с `TIERS`** в `src/lib/calculator.js`. Не
дублировать их вручную: импортировать `TIERS` и собирать `TIER_NAMES` из него,
либо добавить в критерии приёмки проверку на совпадение. Причина дефекта из
раздела 2 — именно в том, что цена на карточке была вписана руками отдельно от
расчёта.

`luxury` в `TIER_NAMES` не входит: через квиз он недостижим и на витрине его нет.
Если когда-нибудь понадобится — добавляется сюда же.

## Часть 3. Квиз

**Файл** `src/pages/B2CQuizPage.jsx`.

### 3.1. Белый список уровней

Строка 53: добавить `euro_top`. Итого `['cosmetic','capital','euro','euro_top','premium']`.
Без этого карточка «Бизнес» из части 2 будет молча падать в `capital` — тот же
дефект, только с другой стороны.

### 3.2. Строка контекста на каждом шаге

Под полосой прогресса (после строки 160, перед карточкой вопроса) добавить
строку плашек с тем, что человек уже выбрал.

Состав строки:

1. **Категория** — всегда первой, `tierTitle(answers.repair_type)`.
2. **Ответы по уже пройденным шагам**, в порядке шагов. Текст плашки берётся из
   самого шага: для `type:'cards'` это `title` выбранной опции, для
   `type:'options'` — `label`, для площади — «60 м²».
3. Шаг `contact` в строку не попадает: там нет выбора, и почта в плашке не нужна.

Пример на середине квиза: `Комфорт · Евроремонт` `Новостройка`
`Монолитно-кирпичные` `White Box` `60 м²`.

Требования:

- Плашки переносятся на вторую строку, а не уезжают за край. На телефоне это
  три-четыре строки, и это нормально.
- Строка не должна оттягивать внимание от вопроса: размер меньше основного
  текста, приглушённый цвет, как у «Шаг 2 из 9».
- Пустой строки быть не может: категория есть всегда.

### 3.3. Когда категорию не выбирали

Если человек зашёл в квиз не с карточки, а из пункта «Калькулятор» в шапке, то
`?tier=` в адресе нет и подставляется `capital` (строка 54). Плашка в таком
случае не должна выглядеть как его выбор.

**Что сделать сейчас:** в этом случае добавлять в плашку пометку «по умолчанию» —
`Эконом · Капитальный · по умолчанию`.

**Открытый вопрос, решение не принято.** Правильнее было бы сделать категорию
обычным шагом квиза, когда её не выбрали заранее. Сейчас квиз про уровень ремонта
не спрашивает вообще: среди девяти шагов такого нет, `answers.repair_type`
приходит только из адреса. То есть человек, зашедший с «Калькулятор», получает
расчёт по капитальному, нигде этого не выбрав. Это отдельная задача, в это ТЗ не
входит, но её стоит поставить в очередь.

## Часть 5. «Бизнес» получает свой уровень в детальной смете

Решение Дмитрия от 24.09.2026: детальная смета для «Бизнеса» должна быть
«Бизнесом», а не сваливаться в «Комфорт».

### Что подтвердил Дмитрий по существу

«Бизнес» отличается от евроремонта **классом материалов, а не набором работ**.
Значит отдельный список позиций ему не нужен: он берёт тот же
`SPEC_ITEMS_FULL`, что и евроремонт, и множители на расценки.

### Почему множитель большой

В детальной смете евроремонта на эталонном случае работы составляют
3 252 118 ₽ (68 %), материалы 1 539 032 ₽ (32 %). Вилка «Бизнеса» на том же
случае — 118 965 — 178 448 ₽/м², тогда как евроремонт даёт 79 852 ₽/м².

Поскольку материалы это только треть сметы, множителя ×1,5 или ×2 не хватает:
даже при ×2,4 на материалы смета остаётся ниже нижней границы вилки. Подобрано
прогоном, таблица была на выбор.

**Выбор Дмитрия: материалы ×2,4, работы ×1,15.** Работы тоже растут, потому что
дорогие материалы требуют более аккуратного монтажа.

### Что сделать

1. **`src/lib/calculator.js`, `tierFromAnswers` (строки 141–147).** Добавить
   `euro_top`. Сейчас функция знает четыре уровня, и `repair_type: 'euro_top'`
   молча вернёт `capital` — тот же дефект, что и белый список из части 3.1,
   только на шаг глубже. **Проверить заодно `luxury`**: он в `TIERS` есть, в
   `tierFromAnswers` нет, и если когда-нибудь станет достижим, поведёт себя так
   же. В этом ТЗ `luxury` не трогаем, но в роадмап записать.

2. **`src/data/specTier.js`.** `tierMap.euro_top` меняется с `'euro'` на
   `'euro_top'`. Фолбэк `SPEC_TIER_FALLBACK` не трогаем.

3. **`src/lib/spec-calculator.js`.**
   - В `TIER_MULTIPLIERS` добавить `euro_top` со всеми восемью классами явно,
     как у остальных уровней: `{ wp: 1.15, mp: 2.4 }` на каждый из
     `finish`, `sanitary`, `engineering`, `rough`, `doors`, `windows`, `prep`,
     `terminal`.
   - `TIER_LABELS.euro_top = 'Евроремонт+'`.
   - Смену состава (`TIER_COMPOSITION`) для `euro_top` не заводить: набор тот
     же, что у евроремонта. `isFullMode` его не исключает, а
     `TIER_COMPOSITION['euro_top']` отсутствует, поэтому подмены не произойдёт
     само собой. Проверить это, а не поверить на слово.

4. **`src/pages/B2CDetailPage.jsx`.** Пятая карточка уровня между «Евроремонт» и
   «Премиум». Текст описания — про класс материалов, а не про состав работ,
   потому что состав тот же. Формулировку предложить, Дмитрий поправит.

5. **`src/pages/B2CResultDetailPage.jsx` и `src/lib/estimateReport.js`.** В
   `MODE_SHOWN_TIERS` добавить `'euro_top'`: у него полный цикл и режим
   застройщика на состав влияет, как у евроремонта.

## Критерии приёмки

1. `TIER_NAMES` содержит пять уровней, и для каждого `low`/`high` совпадают с
   `TIERS` в `calculator.js`. Проверяется прогоном, а не глазами.
2. На главной пять карточек: Старт, Эконом, Комфорт, Бизнес, Премиум, с ценами
   20–30, 35–55, 60–85, 100–150, 160–220 тыс ₽/м². Сетка без висящей карточки на
   1440, 1024 и на телефоне.
3. Клик по «Бизнес» ведёт на `/b2c?tier=euro_top`, квиз считает по
   `euro_top`, и в результате «Категория: Бизнес · Евроремонт+», цена за м²
   в районе 100–150 тыс с учётом модификаторов.
4. Клик по «Старт» ведёт на `/b2c?tier=cosmetic`, результат «Старт ·
   Косметический».
5. На каждом шаге квиза видна строка с категорией и всеми данными до этого
   ответами. После ответа на шаг его плашка появляется в строке.
6. Заход в квиз из пункта «Калькулятор» в шапке: плашка категории содержит
   пометку «по умолчанию».
7. Результат квиза, детальная форма, шапка детальной сметы и печатная смета
   называют уровень одинаково, через `tierTitle`.
8. Детальная форма показывает пять карточек уровня. Пришедшая с `euro_top`
   открыта на «Бизнес · Евроремонт+».
9. `SpecCalc.compute` с `tier: 'euro_top'` на эталонном случае даёт
   **7 433 602 ₽, 123 893 ₽/м², 49 строк**, работы 3 739 930 ₽, материалы
   3 693 674 ₽. Число строк совпадает с евроремонтом: набор позиций тот же.
10. Контрольные цифры четырёх прежних уровней не сдвинулись: `cosmetic`
    1 341 074 ₽, `capital` 3 758 823 ₽, `euro` 4 791 147 ₽, `premium`
    40 770 069 ₽ на эталонном случае (60 м² / 1 с/у / 3 окна / 2 комнаты,
    `replan: 'no'`).
11. `grep -n "euro_top" src/` находит его в `calculator.js` (`TIERS`,
    `tierFromAnswers`, `getSplit`, `estimateDays`, `WINDOW_COST_PER_TIER`),
    `specTier.js`, `spec-calculator.js`, `tierNames.js`, `B2CQuizPage.jsx`,
    `B2CDetailPage.jsx`, `B2CResultDetailPage.jsx`, `estimateReport.js`,
    `HomePage.jsx` — и нигде не остаётся места, где он молча падает в другой
    уровень.
12. В подвале «Клуб» вместо «Программы».
13. `npx vite build` проходит без ошибок.
14. Отчёт `docs/REPORT_tier_naming.md` написан по фактическим результатам.

## Порядок работ

1. Часть 1 — источник названий, сама по себе ничего не меняет на экране.
2. Часть 2 — главная. Проверяется критериями 2, 3, 4.
3. Часть 3 — квиз. Проверяется критериями 5 и 6.
4. Часть 4 — остальные экраны. Проверяется критерием 7.
5. Часть 5 — уровень «Бизнес» в детальной смете. Проверяется критериями 8–11.
   Идёт последней: она единственная трогает расчётный модуль, и если контрольные
   цифры поедут, понятно где искать.
6. Подвал — отдельным коммитом, он ни с чем не связан.

Критерии 2–8 проверяются в браузере. Главная и квиз открыты всем, их можно
смотреть локально; детальная форма за подпиской, она проверяется на боевом после
деплоя.
