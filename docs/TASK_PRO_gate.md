# ТЗ: PRO-гейт по подписке + вёрстка таблицы в админке

Две независимые части. Можно делать в любом порядке, но сборку прогнать один раз в конце.

---

## Часть 1. Включить PRO-гейт по подписке (B2B)

### Проблема

PRO-функции B2B сейчас в демо-режиме и открыты всем, включая незалогиненных:

- `src/pages/B2BResultPage.jsx:14` — `const [showSpec, setShowSpec] = useState(true); // demo: always show` — детальная спецификация показывается всегда;
- офисный калькулятор (`B2BOfficePage`, `B2BOfficeResultPage`, `B2BOfficeDetailPage`) не проверяет доступ;
- кнопка «+ Офис PRO» в кабинете (`B2BCabinetPage`) не проверяет доступ.

Подписка PRO (2 900 ₽/мес) при этом ничего не ограничивает.

### Что сделать

Закрыть PRO-функции проверкой `hasAccess` из `useAuth()` (`src/lib/auth.jsx`). `hasAccess === true`, когда есть подписка со статусом `active` или `trial`.

**1.1. `src/pages/B2BResultPage.jsx`**
- Убрать демо-флаг `showSpec = useState(true)`.
- Блок детальной спецификации (`{showSpec && specResult && (...)}`, ~строка 136) показывать только при `hasAccess`.
- Если `!hasAccess` — на месте блока показать заглушку-CTA: заголовок «Детальная спецификация», короткое описание (расчёт по тендерным расценкам, N позиций), плашка «PRO — 2 900 ₽/мес» и кнопка «Оформить PRO» → `navigate('/pro')`. Для неавторизованных дополнительно кнопка «Войти» (открыть `LoginModal`, как на других страницах).
- Ориентир по стилю и структуре — существующий пейволл в `src/pages/B2CDetailPage.jsx:102-131`.

**1.2. Офисный калькулятор (PRO-функция)**
- `src/pages/B2BOfficePage.jsx`, `B2BOfficeResultPage.jsx`, `B2BOfficeDetailPage.jsx`: если `!hasAccess` — вместо содержимого рендерить тот же пейволл-экран с CTA на `/pro`.
- Пока `authLoading` — показывать текущий лоадер/скелетон, не мигать пейволлом (как в `B2CDetailPage`).

**1.3. `src/pages/B2BCabinetPage.jsx`**
- Кнопка «+ Офис PRO»: при `!hasAccess` вести на `/pro` (апселл), а не открывать калькулятор.

### Не трогать
- Бэкенд (`server.js`, `server/db.js`) — гейт делается на фронте; ручная выдача подписки из админки уже работает.
- Бесплатные функции: быстрый B2B-расчёт (квиз и базовый результат) остаётся доступным всем. Закрываем только детальную спецификацию и офисный калькулятор.

### Критерии приёмки (часть 1)
1. Незалогиненный и залогиненный без подписки: детальная спецификация и офисный калькулятор не отображаются, вместо них — понятный CTA на `/pro`.
2. Пользователь с активной подпиской (в т.ч. выданной вручную из `/admin`) видит все PRO-функции без изменений.
3. Быстрый предварительный расчёт остаётся бесплатным.
4. Нет «мигания» пейволла в момент загрузки авторизации.

## Часть 2. B2B-таблица в админке не помещается по ширине

Файл: `src/pages/AdminPage.jsx`, таблица «Профессионалы» (B2B).

### Проблема
После добавления колонок «Подписка» и «Истекает» строка стала из 10 колонок и не влезает: колонка «Регистрация» и ячейка с кнопками действий (🎁 выдать / отозвать / удалить) уходят за правый край контейнера (`overflowX: auto`) — их не видно без горизонтальной прокрутки.

### Что сделать
Сделать так, чтобы действия были всегда видны. Предпочтителен вариант 1:

1. **Закрепить колонку действий:** последний `<th>` и `<td>` сделать sticky справа (`position: sticky; right: 0`, фон `#fff` для `td` и `#fafafa` для `th`, лёгкая тень слева для отделения от прокручиваемого контента).
2. Либо уплотнить таблицу: «Регистрация» — дата без времени, уменьшить горизонтальные паддинги (`tdStyle`/`thStyle`), при необходимости скрывать «Организация»/«Специализация» на узких экранах.

### Критерии приёмки (часть 2)
1. Кнопки действий видны без горизонтальной прокрутки на десктопе (ширина ~1280px и шире).
2. На мобильных таблица остаётся прокручиваемой, вёрстка не ломается.
3. Та же логика применена к таблице B2C, если она тоже переполняется.
