# ТЗ: подпись плана на `/club` не различает триалы и паиды

Найдено при боевой проверке `trial_b2b` 24.09.2026 (`docs/REPORT_trial_b2b.md`).
Не входит в исходное ТЗ `trial_b2b`, вынесено отдельной задачей по договорённости
с Дмитрием.

## Проблема

`src/pages/ClubPage.jsx`, две карточки статуса завязаны на `status === 'trial'`
и жёстко пишут «Триал», не проверяя `plan`:

- строка 195 (карточка «Ваш статус», hero-visual):
  ```js
  План: {subscription?.status === 'trial' ? 'Триал (14 дней)' : (subscription?.plan === 'club_yearly' || subscription?.plan === 'yearly') ? `Клуб · год (${formatPrice(CLUB_Y)} ₽/год)` : `Клуб · месяц (${formatPrice(CLUB_M)} ₽/мес)`}
  ```
- строка 343 (карточка «Управление подпиской»):
  ```js
  План: {subscription?.status === 'trial' ? 'Триал' : (subscription?.plan === 'club_yearly' || subscription?.plan === 'yearly') ? 'Клуб · год' : 'Клуб · месяц'}
  ```

До части `trial_b2b` любой триал был клубным на 14 дней, и текст был верным по
определению. Теперь `plan` при `status === 'trial'` бывает и `pro_trial` (7
дней), а строка всё равно говорит «Триал (14 дней)» / «Триал». На боевом это
видел профи со свежим PRO-триалом: дата истечения справа верная (1 октября,
7 дней от активации), подпись рядом — нет.

Второй, ещё не проявившийся случай того же корня: обе строки считают, что
неактивный триал плательщик — обязательно клубный месяц или год. Админ может
вручную выдать `pro_monthly` через `/api/admin/users/:id/subscription`
(`server.js`, «Выдать подписку вручную») — такой профи на этой странице тоже
увидит «Клуб · месяц» вместо PRO.

## Что сделать

`src/data/tariffs.js` — один источник правды для подписи плана, вместо двух
мест, дублирующих логику по-разному.

Добавить рядом с `LEGACY_TIER`/`LEGACY_DAYS`:

```js
const LEGACY_LABEL = { monthly: 'Клуб · месяц', yearly: 'Клуб · год', trial: 'Триал (14 дней)' };

// Отображаемое название плана: для актуальных — из PLANS[plan].label,
// для legacy-записей (до разделения тарифов) — из LEGACY_LABEL.
export function labelOf(plan) {
  if (PLANS[plan]) return PLANS[plan].label;
  return LEGACY_LABEL[plan] || 'План';
}
```

`PLANS[plan].label` уже содержит то, что нужно, для каждого актуального плана:
`club_monthly` → «Клуб РПКМ · 1 месяц», `club_yearly` → «Клуб РПКМ · 1 год»,
`pro_monthly` → «РПКМ PRO · 1 месяц», `pro_trial` → «РПКМ PRO · пробные
7 дней». Ничего этого писать заново не нужно.

`src/pages/ClubPage.jsx`:

- строка 195 → `План: {labelOf(subscription?.plan)}`
- строка 343 → `План: {labelOf(subscription?.plan)}`

Импорт `labelOf` добавить в существующую строку `import { PLANS, formatPrice }
from '../data/tariffs'`.

`CLUB_M`/`CLUB_Y` в этих двух строках после правки не используются — проверить
грепом, не остались ли они нужны для чего-то ещё в файле (используются в шапке
тарифов ниже, трогать их объявление не нужно).

## Не трогать

- Саму логику `hasUsedTrial`/`TRIAL_PLANS` (часть 4 `trial_b2b`) — эта задача
  только про текст.
- `tierOf`/`daysOf` и их legacy-таблицы — не путать с новой `labelOf`, это три
  разных, независимых мапы на один и тот же `plan`.
- Текст `Триал активен` / `Подписка активна` над карточками (строки 163, 189) —
  верен для обоих случаев, не про длительность.
- Открытый вопрос про кнопку триала на `ProPage.jsx` — отдельный вопрос, не
  относится к этой задаче.

## Критерии приёмки

1. Профи на активном `pro_trial` видит на `/club` (обе карточки статуса)
   подпись плана «РПКМ PRO · пробные 7 дней», не «Триал (14 дней)» / «Триал».
2. Физлицо на активном клубном триале видит «Триал (14 дней)» / «Триал» — как
   раньше, без регресса.
3. Физлицо с оплаченным клубным месяцем/годом видит название своего плана из
   `PLANS` (без цены), одинаковое для legacy и актуальных записей. Цена в
   карточке «Ваш статус» убрана из этой подписи осознанно — она и так есть
   рядом, в блоке `hero-stats`.
4. `PLANS` по-прежнему нигде не перебирается циклом (`labelOf` обращается по
   ключу, как `tierOf`/`daysOf`).
5. `npx vite build` проходит без ошибок.

## Порядок работ

Один коммит, правка укладывается в один файл-источник и два места
использования. Деплой и боевая проверка — по отдельной команде, как обычно.
