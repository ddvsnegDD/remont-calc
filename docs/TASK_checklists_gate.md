# ТЗ: закрыть чек-листы подпиской

**Источник:** `docs/TASK_tariffs.md`, часть 2, неисполненный пункт. Обнаружено при закрытии того ТЗ 22.09.2026, см. `docs/REPORT_tariffs.md`.
**Дата:** 2026-09-22.

Маленькое ТЗ, два файла. Искать по grep-якорям.

---

## Проблема

Чек-листы приёмки заявлены на `/club` как содержимое подписки, но доступ к ним не проверяется. В `src/pages/ChecklistsPage.jsx` (якорь `const { user } = useAuth();`) и в `src/pages/ChecklistDetailPage.jsx` (тот же якорь) из контекста берётся только `user`, дальше стоит единственная проверка `if (!user)`, показывающая приглашение войти.

Ни `hasClub`, ни `hasPro`, ни `subscription` в этих файлах не встречаются:

```
grep -n "hasClub\|hasPro\|hasAccess\|subscription" src/pages/ChecklistsPage.jsx src/pages/ChecklistDetailPage.jsx
```
даёт пусто.

Из этого следует: любой, кто зарегистрировался по одноразовому коду и не заплатил, получает все шесть чек-листов, 175 пунктов, фотофиксацию и печать акта. Главная ценность тарифа «Клуб» раздаётся за один email.

Решение владельца от 22.09.2026: это недоделка, чек-листы должны быть закрыты подпиской.

---

## Что сделать

### 1. `src/pages/ChecklistsPage.jsx`

Заменить

```js
const { user } = useAuth();
```
на
```js
const { user, hasClub, loading: authLoading } = useAuth();
```

Порядок веток:

- **Первой** — пока `authLoading` истинно, рисовать лоадер, а не пейволл. Иначе подписчик на долю секунды увидит предложение оплатить то, за что уже заплатил. Образец: `src/pages/B2BOfficePage.jsx`, якорь `if (authLoading) {`.
- **Существующую ветку `if (!user)` оставить как есть**, она про вход, а не про оплату. Тексты не менять.
- **После неё добавить** `if (!hasClub)` с пейволлом, ведущим на `/club`.

Пейволл собрать не руками, а готовым компонентом: `src/components/ProPaywall.jsx` принимает проп `target` (якорь `target = 'pro'`), и значение `'club'` переключает кнопку на `/club`. Третью копию одной и той же разметки в проекте разводить не надо.

Ориентир по смыслу текста, не копировать дословно: заголовок про чек-листы приёмки, строка о том, что входит (6 чек-листов, 175 пунктов, фотофиксация нарушений, печать акта), цена из `PLANS.club_monthly.price` через `formatPrice`, кнопка «Попробовать 14 дней бесплатно» на `/club`. Как это сделано в `src/pages/B2CDetailPage.jsx`, якорь `if (!hasAccess) {`.

### 2. `src/pages/ChecklistDetailPage.jsx`

То же самое: расширить деструктуризацию, ветку `if (!user)` оставить, после неё добавить `if (!hasClub)`.

**Это обязательно, а не дубль ради симметрии.** Страница открывается по прямой ссылке `/checklists/:id`, и если закрыть только список, ссылка из закладок или из чужого сообщения по-прежнему пустит внутрь. Печать акта живёт здесь же и закрывается вместе со страницей.

### 3. Почему именно `hasClub`, а не `hasAccess`

Оба сейчас дают одно и то же: `hasAccess` объявлен алиасом в `src/lib/auth.jsx`, якорь `const hasAccess = hasClub;`. Но имя `hasAccess` не говорит, к чему именно доступ, и на этом уже споткнулся аудит. В новом коде использовать `hasClub`. Существующие места с `hasAccess` в этом ТЗ не переименовывать, это отдельная уборка.

Триал даёт уровень `club` (`LEGACY_TIER` и `tierOf` в `src/data/tariffs.js`), поэтому четырнадцатидневный пробный период доступ к чек-листам сохраняет. Так и задумано.

## Не трогать

- Структуру хранения в `localStorage` и ключи (якорь `getStorageKey` в обоих файлах). **Данные пользователей не удалять ни при каких условиях.** Человек мог заполнить чек-лист на триале; после истечения подписки страница закрывается, но заполненное остаётся в браузере и должно вернуться нетронутым, когда он оплатит.
- Данные чек-листов в `src/data/checklists.js`.
- Логику печати акта в `src/lib/checklistReport.js`.
- Тексты на `/club`, где чек-листы заявлены как содержимое подписки. Они не врут, они просто станут правдой.
- Ветки `if (!user)` и их формулировки.

## Критерии приёмки

1. Залогиненный пользователь без подписки открывает `/checklists` и видит пейволл с кнопкой на `/club`, а не список чек-листов.
2. Тот же пользователь по прямой ссылке `/checklists/<любой_id>` видит тот же пейволл, внутрь не попадает.
3. Незалогиненный видит прежнее приглашение войти, текст не изменился.
4. Пользователь на триале видит чек-листы и может с ними работать.
5. Подписчик Клуба и подписчик PRO видят чек-листы.
6. При загрузке страницы пейволл не мелькает: пока авторизация грузится, виден лоадер.
7. Заполненный чек-лист не теряется. Проверка: заполнить несколько пунктов, отозвать подписку из `/admin`, убедиться, что страница закрылась, вернуть подписку, убедиться, что отметки на месте.
8. `grep -n "hasClub" src/pages/ChecklistsPage.jsx src/pages/ChecklistDetailPage.jsx` находит обе страницы.
9. `npx vite build` проходит.
