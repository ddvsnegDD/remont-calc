## 3. Найдено дополнительно

### 3.1. Обещание возврата противоречит оферте и не исполняется системой (критично)

Три места расходятся между собой и с задеплоенной час назад офертой:

- `src/pages/ClubPage.jsx:28` (FAQ): «Да, отмена одной кнопкой. **Деньги вернутся на карту в течение 3 дней.**»
- `src/pages/ClubPage.jsx:170` (тост после отмены): «Подписка отменена. **Деньги вернутся на карту в течение 3 дней.**»
- Оферта, п. 6.1/6.4/6.5: возврат **пропорционален дням использования**, оформляется
  **письмом на email**, срок — **10 рабочих дней** с момента подтверждения запроса.

При этом `cancelSubscription()` в `server/db.js:164` не инициирует возврат вообще:

```sql
UPDATE subscriptions SET status = 'cancelled', expires_at = NOW()
```

То есть при отмене (а) деньги автоматически не возвращаются, вопреки тексту тоста,
и (б) `expires_at = NOW()` **немедленно обрывает доступ к уже оплаченному периоду**.
Пользователь, отменивший подписку на третий день оплаченного месяца, теряет доступ
сразу и не получает ничего из обещанного на экране.

Это ровно тот класс проблемы, ради которого писалось ТЗ («продаём больше, чем
обязуемся»), только с деньгами вместо функций, и теперь ещё и в прямом противоречии
с текстом договора. Требует решения до того, как появится первый платящий пользователь.

## 5. Что изменилось в `sendRawEmail` (по п. 7.5 ТЗ)

Функция расширена в коммите `59594e0` одним необязательным параметром:

```js
// было
export async function sendRawEmail(to, subject, html)
// стало
export async function sendRawEmail(to, subject, html, replyTo)
```

`replyTo` прокидывается дальше в `p.send(to, subject, html, 'РПКМ', replyTo)` и
подставляется в каждый из четырёх поддерживаемых провайдеров в его собственном
формате поля: `replyTo`, `reply_to` и `replyTo: { email }` — соответственно тому,
что ожидает API каждого. Везде через spread с проверкой (`...(replyTo ? {...} : {})`),
поэтому при вызове без четвёртого аргумента поведение прежних вызовов не изменилось.

Нужно это форме обратной связи: письмо приходит владельцу сайта, но «Ответить»
в почтовом клиенте должно подставлять адрес отправителя сообщения, а не адрес
получателя. Для писем с расчётом `replyTo` не передаётся.
