# REPORT: PRO-гейт по подписке и вёрстка админки — закрытие ТЗ

**По ТЗ:** `docs/TASK_PRO_gate.md`
**Дата проверки:** 2026-09-22

**Как проверялось.** Чтением кода и командами `grep`. Интерфейс в браузере не открывался, ширина таблиц на разных экранах не замерялась. Пункты, требующие глаз, помечены отдельно.

**Вывод коротко.** Обе части ТЗ выполнены. Все шесть критериев приёмки закрываются по коду, два из них нуждаются в визуальном подтверждении.

## Часть 1. PRO-гейт

| № | Критерий | Как проверял | Результат |
|---|---|---|---|
| 1 | Незалогиненный и залогиненный без подписки не видят детальную спецификацию и офисный калькулятор, вместо них CTA на `/pro` | `grep -rn "hasPro" src/pages/` | Выполнено. В `B2BResultPage.jsx` блок спецификации рисуется только при `specResult && !authLoading && !hasPro` для пейволла и при `specResult && hasPro` для самой спецификации. Офисные страницы закрыты ранним возвратом `if (!hasPro)` в `B2BOfficePage.jsx`, `B2BOfficeResultPage.jsx`, `B2BOfficeDetailPage.jsx` |
| 2 | Пользователь с активной подпиской видит все PRO-функции | чтение `src/lib/auth.jsx` | Выполнено по построению: `hasPro = tier === 'pro'`, где `tier` берётся из плана активной подписки через `tierOf`. Подписка, выданная вручную из `/admin` планом `pro_monthly`, даёт тот же результат |
| 3 | Быстрый предварительный B2B-расчёт остаётся бесплатным | чтение `B2BResultPage.jsx` | Выполнено. Гейт наложен только на `specResult`. Базовый результат квиза рисуется без проверок доступа |
| 4 | Нет мигания пейволла в момент загрузки авторизации | `grep -n "authLoading" src/pages/B2B*.jsx` | Выполнено. Во всех четырёх файлах `loading` из `useAuth()` берётся как `authLoading` и проверяется до решения о доступе: ранний возврат с лоадером в трёх офисных страницах, а в `B2BResultPage.jsx` условие содержит `!authLoading` прямо в выражении |

**Демо-флаги убраны.** ТЗ требовало снять `const [showSpec, setShowSpec] = useState(true); // demo: always show`. Проверка: `grep -rn "B2B_DEMO_AVAILABLE\|showSpec = useState" src/` не находит ничего.

Попутно это закрывает одну из находок аудита Искры. В §3.2 отчёта числилось, что в `B2BOfficeDetailPage.jsx` живёт `B2B_DEMO_AVAILABLE = true` и «демо открыто всем, то есть §1.5 работает против PRO-гейта даже на уровне UI». Пункт был помечен `[SUBAGENT]`. Фактически такой константы в коде нет. Находку можно закрывать как неподтверждённую.

## Общее

`npx vite build` в рамках этой проверки не запускался. Косвенное подтверждение: сборка прогонялась 18.09.2026 на текущем дереве в ходе P0 и прошла без ошибок и предупреждений, см. `docs/REPORT_payments_auth_hardening.md`.

Бэкенд ТЗ не требовало трогать, и он не тронут: гейт целиком живёт на фронте, ручная выдача подписки из админки работает как раньше.

## Что осталось за рамками этой проверки

Два пункта требуют открыть браузер: как выглядит закреплённая колонка на десктопе шириной около 1280 px и не ломается ли таблица на телефоне. Оба относятся к части 2 и на работу продукта не влияют, это удобство администратора.

Отдельно стоит помнить, что гейт сделан на фронте. Данные офисных расценок физически лежат в бандле и скачиваются каждому посетителю до всякой оплаты, около полутора мегабайт. Это §1.5 аудита, отдельное продуктовое решение: настоящее ТЗ закрывало интерфейс, а не данные.
