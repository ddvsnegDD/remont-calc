# ТЗ: вход через B2C-форму сбрасывает роль B2B-пользователя

## Проблема

`server/db.js`, функция `createUser` (upsert по email):

```sql
role = COALESCE(EXCLUDED.role, users.role)
```

а в параметры передаётся `role || 'b2c'`.

При входе через обычную форму B2C (`LoginModal`, `/api/auth/verify` без поля `role`) в `EXCLUDED.role` попадает `'b2c'` — не NULL, поэтому `COALESCE` выбирает его и **перезаписывает существующую роль `b2b`**.

Последствие: любой B2B-пользователь (профи), который вошёл через B2C-модалку — например, нажав «Войти» на PRO-пейволле, — молча превращается в физлицо. В админке он переезжает из «Профессионалов» в «Физические лица», теряется B2B-контекст кабинета. Воспроизведено на проде.

`organization` и `position` при этом сохраняются, потому что приходят пустыми и `COALESCE` оставляет старые значения.

## Что сделать

Роль не должна понижаться при обычном входе. Правило: `b2b` — только повышение, назад автоматически не откатываем.

В `server/db.js`, `createUser`, заменить строку для `role` на логику вида:

```sql
role = CASE WHEN EXCLUDED.role = 'b2b' THEN 'b2b' ELSE users.role END
```

То есть:
- существующий `b2b` сохраняется при любом входе (в т.ч. через B2C-форму);
- переход `b2c → b2b` по-прежнему возможен при регистрации/входе как профи (`B2BLoginPage` передаёт `role: 'b2b'`);
- у нового пользователя без явной роли остаётся дефолт `'b2c'` (поведение при INSERT не меняется).

Проверить, что `organization` и `position` по-прежнему не затираются пустыми значениями.

## Не трогать
- Фронтенд: `LoginModal`, `B2BLoginPage` — они работают корректно, проблема на стороне upsert'а.
- Подписки: привязаны к `user_id`, роль на них не влияет.

## Критерии приёмки
1. Пользователь с ролью `b2b` входит через B2C-модалку → роль остаётся `b2b`, в админке он в «Профессионалах».
2. Пользователь с ролью `b2c` регистрируется/входит как профи → роль становится `b2b`, сохраняются организация и специализация.
3. Новый пользователь, вошедший через B2C-форму, получает роль `b2c`.
4. Повторные входы не затирают `name`, `phone`, `organization`, `position`.
5. `node --check server/db.js` проходит; `npx vite build` без ошибок.

## Примечание
Роль пострадавшего аккаунта восстанавливается вручную:
`UPDATE users SET role='b2b' WHERE email='ddv1121@yandex.ru';`
