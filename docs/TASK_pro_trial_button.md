# ТЗ: кнопка PRO-триала на экране лимита и на /pro (q04)

Решение Дмитрия 02.10.2026: вариант 1. Кнопку «Попробовать PRO 7 дней бесплатно» показываем и на пейволле PRO (экран «Лимит бесплатного плана» и остальные места, где профессионал упирается в PRO), и на /pro.

## Проблема

Пробный PRO на 7 дней уже работает, но доступен только на /club (ClubPage.jsx, строки ~189-194 и ~237-240, `isProUser = user?.role === 'b2b'`). Профессионал упирается в тупик в других местах:

1. Экран «Лимит бесплатного плана использован» (B2BQuizPage.jsx, строка ~185) рисует `ProPaywall` с единственной кнопкой «Оформить PRO». Бесплатный профи делает один расчёт в месяц, второй упирается в этот экран. Триала на экране нет, о нём человек не знает.
2. Тот же `ProPaywall` стоит на детальной спецификации (B2BResultPage.jsx, ~146), детальном офисном расчёте (B2BOfficeDetailPage.jsx, ~346) и офисном калькуляторе (B2BOfficePage.jsx, ~163). Везде только «Оформить PRO».
3. /pro для вошедшего профи без PRO показывает «Оформить PRO за 2 900 ₽/мес» (ProPage.jsx, строка ~86) и «Перейти на PRO» в блоке сравнения (строка ~169). Триала нет.

Серверная часть готова: `POST /api/subscription/trial` (server.js, ~292) для `role === 'b2b'` создаёт `pro_trial` на 7 дней, один раз на аккаунт, при активной подписке отвечает отказом. Серверный код не меняем.

## Что сделать

Одним коммитом. После: `npx vite build`, коммит, не пушить, остановиться, отчёт в docs/REPORT_pro_trial_button.md.

### 1. src/lib/auth.jsx: общая логика триала

- Новая функция в контексте `startTrial()`: делает `POST /api/subscription/trial` с `credentials: 'include'`, при `data.ok` вызывает `markTrialUsed()` и `refreshSubscription()`, возвращает объект ответа сервера (`{ ok, plan, error }`). При сетевой ошибке возвращает `{ ok: false, error: 'Ошибка активации триала' }`.
- Новое вычисляемое значение `canTryProTrial`: `user?.role === 'b2b' && !trialUsed && !subscription && queue.length === 0`. Это единственное место, где решается «показывать ли кнопку триала профи». Оба экрана и /club пользуются им.
- Обе вещи отдать через контекст рядом с остальными.

### 2. src/components/ProPaywall.jsx

- Для `target === 'pro'`, когда `canTryProTrial` истинно: главная кнопка «Попробовать PRO 7 дней бесплатно» (`terra`), рядом вторая «Оформить PRO» (`outline`, ведёт на /pro как сейчас). Под бейджем «PRO — 2 900 ₽/мес» короткая серая строка: «Без карты. Пробный доступ даётся один раз на аккаунт».
- Нажатие вызывает `startTrial()`. Пока идёт запрос, кнопка отключена. При `ok: false` ответ сервера показывается текстом под кнопками (красная рамка, как `renderNotice` в ClubPage.jsx), не тостом.
- При успехе компонент вызывает необязательный проп `onTrialStarted`. Дальше страница сама перерисуется, потому что `hasPro` в контексте станет истинным.
- Для `target === 'club'`, для гостя (`!user`) и для профи с использованным триалом поведение не меняется. Профи с использованным триалом видит как раньше «Оформить PRO».
- Физлицо (`role !== 'b2b'`) кнопку PRO-триала не видит: его триал клубный и PRO не открывает.

### 3. src/pages/B2BQuizPage.jsx (экран лимита)

- `ProPaywall` получает `onTrialStarted={() => { setLimitHit(false); saveAndShow(answers); }}`. Расчёт при лимите на сервере не сохраняется (server.js, ~682, отказ до `createCalculation`), поэтому повторная отправка не создаёт дубль, а сервер уже видит `pro_trial` и лимит не применяет. Человек после нажатия сразу попадает на результат расчёта, ничего не вводя заново.
- Если после повторной отправки снова `limit`, остаётся прежний экран (штатное поведение `saveAndShow`).
- Текст `sub` на этом экране для `canTryProTrial` дополнить: «Попробуйте PRO бесплатно 7 дней: расчёт сохранится сразу». Для остальных текст прежний.

### 4. Остальные пейволлы PRO

B2BResultPage.jsx, B2BOfficeDetailPage.jsx, B2BOfficePage.jsx: проп `onTrialStarted` не нужен. Страницы уже читают `hasPro` из контекста и откроют содержимое сами после `refreshSubscription()`. Проверить, что это так (особенно B2BResultPage: блок спецификации `specResult && hasPro`), и если где-то состояние берётся не из контекста, поправить.

### 5. src/pages/ProPage.jsx

- В `heroCta` для вошедшего без PRO при `canTryProTrial`: главная кнопка «Попробовать PRO 7 дней бесплатно», рядом вторая «Оформить PRO за {PRO_PRICE} ₽/мес» (`handlePay`). Для остальных вариантов (гость, hasPro, триал использован) без изменений.
- Серая строка под кнопками (строка ~104) при `canTryProTrial`: «Без карты. Пробный доступ даётся один раз на аккаунт. Если у вас действует Клуб, он заменяется на PRO с момента оплаты».
- Кнопка в блоке сравнения (строка ~169): при `canTryProTrial` текст «Попробовать PRO 7 дней бесплатно», действие `startTrial`. Ответ сервера показывать существующим `notice` страницы (строки ~34-38 и вывод).
- После успешного триала на /pro должен появиться зелёный блок «✓ PRO активен до …» (из `subscription`, без перезагрузки страницы). Если `refreshSubscription` не успел, `heroCta` не должен показывать триальную кнопку повторно: `markTrialUsed()` это уже гарантирует через `canTryProTrial`.

### 6. src/pages/ClubPage.jsx

- `handleTrial` перевести на `startTrial()` из контекста, поведение и тексты не менять (тексты «PRO на 7 дней активирован!» и «Триал на 14 дней активирован!» остаются, ответ через `renderNotice('trial')`). Цель: одна реализация вместо двух.
- Условия показа кнопок на /club не менять.

## Что не трогать

- Тексты оферты, политики и согласия. Условия пробного периода в оферте (OfferPage.jsx, ~72) уже говорят про 7 дней для профессионалов.
- Блоки «Персональный менеджер» и «SLA 24 часа» на /pro. Это отдельное решение по хвостам разворота (q05).
- Пейволл `target="club"` (чек-листы) и логику для физлиц.

## Критерии приёмки

Читаю код при приёмке. Боевая проверка после деплоя, на новом профессиональном аккаунте без подписок (нужен вход через /b2b-login):

1. Новый профи делает один расчёт, затем второй. На экране «Лимит бесплатного плана использован» есть кнопка «Попробовать PRO 7 дней бесплатно» и рядом «Оформить PRO».
2. Нажатие даёт результат второго расчёта без повторного ввода. В /b2b-profile или кабинете виден «Пробный доступ к PRO».
3. На /pro для этого профи (после триала) блок «✓ PRO активен до …» и кнопка «Продлить PRO за 2 900 ₽». Здесь же закрывается недопроверенный пункт очереди (q24): строка «Новый период начнётся …» появится после оплаты, платить не нужно, достаточно увидеть «Продлить».
4. Второй профессиональный аккаунт: открыть /pro без триала, нажать «Попробовать PRO 7 дней бесплатно» прямо на /pro, увидеть «✓ PRO активен» без перезагрузки.
5. Профи с использованным триалом (или тот же аккаунт после окончания): на пейволле и на /pro только «Оформить PRO», кнопки триала нет.
6. Физлицо на пейволле PRO (например, открыть /b2b-office-detail под физическим аккаунтом) видит только «Оформить PRO». Гость видит «Войти».
7. Сборка `npx vite build` проходит. На /club кнопки триала работают как раньше.

## Риски

- Триал привязан к аккаунту, а аккаунт создаётся по любому email и коду. Тот, кто хочет безлимит, заводит новый email. Это уже так на /club, кнопка на пейволле делает путь короче. Вопрос защиты (например, ограничение по телефону) здесь не решаем, отдельная задача, если станет нужно.
- Автоповтор расчёта после триала (часть 3) сохраняет расчёт сразу после активации. Если пользователь передумал, расчёт останется в его кабинете. Это приемлемо: расчёт принадлежит ему.
