# Отчёт: мобильная вёрстка — страницы шире экрана телефона

**ТЗ:** `docs/TASK_mobile_layout.md`, части 1–3.
**Дата выполнения:** 2026-09-26 — 2026-09-27.
**Коммиты:** `0fa8ee4` (часть 1), `dbfaa9f` (часть 2), `bd59470` (часть 3).
**Деплой:** часть 1–2 задеплоена (`5f8955e`), боевая проверка на iPhone 26–27.09 — см. раздел ниже. Часть 3 (`bd59470`) на момент этого отчёта не задеплоена.

## Среда проверки

Нет `.env`, нет локального PostgreSQL. Дев-сервер (`npm run dev`, порт 3000) поднимался без бэкенда — `/api/auth/me` и подобные отвечают `500`, страницы, требующие входа, показывают свою ветку «Авторизуйтесь для доступа» или пейволл. Проверка велась в браузерной панели (эмуляция viewport 390×844, 360×800, 1280×900) через `document.documentElement.scrollWidth`, `getComputedStyle(...).gridTemplateColumns` и скриншоты.

Для мест, недоступных без входа, использованы два приёма:
1. **Живая форсированная проверка на смонтированном элементе** — временно (через рантайм, не в файлах) выставлялось старое значение `grid-template-columns` инлайн-стилем на уже отрисованном элементе доступной страницы, замерялся `scrollWidth`, затем откатывалось — так получены честные числа «было/стало» без правки исходников.
2. **Изолированная HTML-репродукция** (по образцу части 1) — для трёх страниц, полностью закрытых платным гейтом (`B2CDetailPage.jsx`, `B2BOfficePage.jsx`, `B2BOfficeDetailPage.jsx`), не открыть которые без БД в принципе: разметка и классы из исходников скопированы в статический HTML с реальным собранным `global.css` (`npx vite build` → `dist/assets/*.css`), отдано локальным `http.server`, замерено на 390/360/1280px.

## Часть 3. Невидимые чекбоксы и дата на iOS/WebKit (`bd59470`)

Найдено боевой проверкой на iPhone 26.09 (после деплоя `5f8955e`) — оба дефекта видны только в Safari/WebKit, эмулятор Chromium их не показывает, поэтому в частях 1–2 они не были пойманы.

**3.1. Невидимые чекбоксы.** `src/lib/theme.js`: в палитре `C` не было ключа `gray300` — `ChecklistDetailPage.jsx:90` получал `border: 2px solid undefined` для неотмеченного чекбокса. Chrome подставляет свою рамку кнопки по умолчанию (баг не виден на компьютере), WebKit на iOS — нет (белый квадрат на белом фоне). Добавлен `gray300: "#D1D5DB"` (между `gray200` #E4E4E7 и `gray400` #9CA3AF).

`grep -rhoE "C\.[a-zA-Z0-9]+" src | sort -u` нашёл только этот один несуществующий ключ, но обращений к нему — **15 в 5 файлах** (все чинятся одной правкой палитры, ни один не трогался отдельно):
- `ChecklistDetailPage.jsx:90,609` — рамка чекбокса пункта и кнопки результата приёмки;
- `B2BOfficeDetailPage.jsx:524,635` — цвет суммы при площади 0, пунктирная рамка кнопки;
- `AdminPage.jsx:311,312,319,382,383,384,385,392` — серый цвет пустых полей в таблицах пользователей;
- `ChecklistsPage.jsx:193,195,199` — иконки сброса и стрелки в списке чек-листов.

Кнопке чекбокса также добавлены `appearance:'none'`/`WebkitAppearance:'none'`/`padding:0`, чтобы не зависеть от стилей кнопки браузера.

**3.2. Дата вылезает за край на iOS.** Новый класс `.checklist-meta-input` (`global.css`) на все три поля блока «Объект»: `-webkit-appearance:none`/`appearance:none` снимает нативную отрисовку `input[type=date]` (серый фон, распирание колонки мимо `minWidth:0`/`width:100%` из части 1), `::-webkit-date-and-time-value{text-align:left}` выравнивает текст. Полю «Помещение» добавлена подпись «Помещение» (симметрично подписи «Дата приёмки») — иначе в общей строке грид растягивал поля до разной высоты.

**Проверка:** Playwright/WebKit не установлен и не закэширован в этом окружении (`ms-playwright` не найден нигде на диске — проверено `find / -maxdepth 8 -iname "ms-playwright"`) — браузерный бинарник качать не стал. Проверено только в Chromium: изолированная HTML-репродукция с реальным собранным `global.css` показывает, что блок «Объект» не переполняется на 390/360/1280px, поля выровнены по высоте, computed `border-color` чекбокса и поля даты — точные новые hex-значения (`rgb(209,213,219)` / `rgb(228,228,231)`), а не браузерный фолбэк; дата кликабельна и вводится (сегмент дня получает фокус по клику). Саму разницу WebKit-бага в Chromium показать нельзя — она там не воспроизводится, это прямо предусмотрено в самом ТЗ. Окончательная проверка — на iPhone Дмитрия после деплоя (см. `TASK_small_debt.md`, п. 2.2 — тем же боевым прогоном 27.09 найден смежный дефект высоты пустой даты, чинится отдельной задачей).
