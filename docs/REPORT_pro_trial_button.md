# Отчёт: кнопка PRO-триала на экране лимита и на /pro (q04)

**Коммит:** `1c4db9c` (без push). Серверный код не менялся.

## Что изменено

- [`src/lib/auth.jsx`](../src/lib/auth.jsx): в контекст добавлены `startTrial()` и `canTryProTrial`.
  - `startTrial()`: `POST /api/subscription/trial` (`credentials: 'include'`); при `ok` вызывает
    `markTrialUsed()` и ждёт `refreshSubscription()`; возвращает ответ сервера как есть
    (`{ ok, plan, error }`); сеть/не-JSON → `{ ok: false, error: 'Ошибка активации триала' }`.
  - `canTryProTrial = user?.role === 'b2b' && !trialUsed && !subscription && queue.length === 0` — единственное
    место решения «показывать ли профи кнопку триала».
- [`src/components/ProPaywall.jsx`](../src/components/ProPaywall.jsx): для `target === 'pro'` и `canTryProTrial` —
  главная кнопка «Попробовать PRO 7 дней бесплатно» (`terra`, отключается на время запроса) и рядом
  «Оформить PRO» (`outline`, на /pro); под бейджем серая строка «Без карты. Пробный доступ даётся один раз на
  аккаунт»; ошибка сервера — красной рамкой под кнопками, не тостом. Новый необязательный проп
  `onTrialStarted`. Для `target="club"`, гостя, физлица и профи с использованным триалом поведение прежнее.
- [`src/pages/B2BQuizPage.jsx`](../src/pages/B2BQuizPage.jsx) (экран лимита): `onTrialStarted` снимает `limitHit`
  и повторно вызывает `saveAndShow(answers)`; текст `sub` при `canTryProTrial` дополнен «Попробуйте PRO
  бесплатно 7 дней: расчёт сохранится сразу.»
- [`src/pages/ProPage.jsx`](../src/pages/ProPage.jsx): для вошедшего без PRO при `canTryProTrial` — в шапке
  «Попробовать PRO 7 дней бесплатно» + «Оформить PRO за … ₽/мес» (`outline`); серая строка — «Без карты. Пробный
  доступ даётся один раз на аккаунт. Если у вас действует Клуб, он заменяется на PRO с момента оплаты»; в блоке
  сравнения кнопка «Попробовать PRO 7 дней бесплатно» (`startTrial`). Результат показывается существующим
  `notice`. Остальные варианты без изменений.
- [`src/pages/ClubPage.jsx`](../src/pages/ClubPage.jsx): `handleTrial` переведён на `startTrial()`; тексты
  уведомлений и условия показа кнопок не менялись.
- Пейволлы B2BResultPage, B2BOfficeDetailPage, B2BOfficePage: `onTrialStarted` не нужен. Проверено чтением кода:
  все три берут `hasPro` из контекста (`B2BResultPage:145/156`, `B2BOfficeDetailPage:343`, `B2BOfficePage:160`),
  устаревших копий состояния нет — содержимое откроется после `refreshSubscription()`.

## Проверка

- `npx vite build` — без ошибок.
- Реальные страницы в браузере, API заменён заглушкой (профи без подписки, `POST /api/subscription/trial`
  включает `pro_trial`, `POST /api/calcs` отвечает `limit` до триала). Везде 390 px, `scrollWidth === 390`:
  - пейволл `/b2b-office` (профи без триала): «Попробовать PRO 7 дней бесплатно» + «Оформить PRO», серая строка;
    нажатие → `POST trial` → `GET /subscription/status` → страница сама показала «Расчёт стоимости офисного
    fit-out»;
  - экран лимита в квизе (прошёл все 13 шагов): кнопки и дополненный текст есть; нажатие → `POST trial`, повторный
    `POST /api/calcs`, переход на `/b2b-result` без повторного ввода;
  - `/pro` до триала: «Попробовать…» + «Оформить PRO за 2 900 ₽/мес», серая строка, кнопка в сравнении; нажатие →
    «✓ PRO активен до …» без перезагрузки, затем «Продлить PRO за 2 900 ₽» и «Продлить PRO»;
  - профи с использованным триалом и физлицо на пейволле: только «Оформить PRO»;
  - отказ сервера (подменён ответ `fetch`): «⚠ У вас уже есть активная подписка» красной рамкой под кнопками;
  - `/club`: кнопка «Попробовать 14 дней бесплатно» работает через `startTrial`, плашка «Триал активен».
- Заглушка не боевая; текст уведомления на `/club` в проверке «PRO на 7 дней…» — артефакт заглушки (она всегда
  отвечает `pro_trial`).

## Не проверено

- Гость на пейволле («Войти») и сценарии с реальным сервером — только чтением кода, боевая проверка по ТЗ после
  деплоя.
- Состояние гонки на ответе `refreshSubscription`: `startTrial` ждёт обновления подписки до возврата, поэтому
  триальная кнопка не должна мелькать повторно; в заглушке не воспроизводилось.
