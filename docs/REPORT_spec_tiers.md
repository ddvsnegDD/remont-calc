## Часть 1 — новые классы `prep` и `terminal`

**Было:** в `SPEC_ITEMS_FULL`/`SPEC_ITEMS_WHITEBOX` шесть классов (`cls`): `rough`, `finish`, `sanitary`, `engineering`, `doors`, `windows`. `TIER_MULTIPLIERS` трогал только `finish` и `sanitary`, хотя 41% суммы детальной сметы лежит в `rough`.

**Стало:** выделены два новых класса, программной переклассификацией `cls`-поля (42 замены: 9+12 позиций × 2 массива), сверка каждой — по `name`+`unit`+`mat`/`vol`, не по индексу:
- `prep` (подготовка поверхностей) — 9 позиций из `rough`: грунтовка/шпатлёвка потолка и стен, оклейка стеклохолстом (жилые + санузел), штукатурка стен санузла.
- `terminal` (оконечка) — 12 позиций: 8 из `sanitary` (монтаж умывальника, смесителей ×3, полотенцесушителя, унитаза, инсталляции, ванны), 4 из `engineering` (светильник, выключатель, розетка, рамка).
- `TIER_MULTIPLIERS` каждого уровня (`capital`, `euro`) явно перечисляет все восемь классов; для новых на этом шаге — единицы.

**Коммит:** `3f63f4a`. Уточнение к ТЗ (обнаружено по факту прогона, не заранее) — коммит `be8305c`.

**Проверено:**
```
SPEC_ITEMS_FULL: 50 позиций, {"terminal":12,"sanitary":2,"engineering":3,"doors":3,"rough":11,"prep":9,"finish":8,"windows":2}
SPEC_ITEMS_WHITEBOX: та же раскладка
```
Контроль числами на 60 м² / 1 с/у / 3 окна / 2 комнаты, `mode: 'full'`, `replan: 'no'`:
- `capital` — **4 952 991 ₽ (82 550 ₽/м²)**, не сдвинулся (все его множители и так были единицами — сдвигаться было неоткуда).
- `euro` сдвинулся на −76 451 ₽ (с 5 566 965 до 5 490 514 ₽): восемь позиций из `sanitary` несли множитель `euro` на материалы ×2,00, а новый `terminal` на этом шаге — ×1,00. Один множитель класса не может одновременно сохранить поведение двух разных источников. Признано ожидаемым и не компенсировалось искусственно — часть 2 всё равно приводит `euro` к единичным множителям.

## Часть 2 + 3.1 — переименование уровней и смена состава капитального

**Было:** набор `SPEC_DATA.full` (по факту — евроремонт: ГКЛ по каркасу в два слоя с утеплением на стенах, подвесной ГКЛ на потолке) был подписан как `capital` с единичными множителями, а `euro` получал сверху надбавку `finish ×1,30/×2,00`. Перевёрнуто: то, что физически является евроремонтом, называлось капитальным, а настоящий евроремонт получал двойную наценку сверху себя же.

**Стало:**
- `euro` = `full` как есть, без надбавок. `TIER_MULTIPLIERS.euro` — все восемь классов ×1,00 (было `finish: 1.30/2.00`, `sanitary: 1.00/2.00`).
- `capital` = `full` со сменой состава. Новый экспорт `TIER_COMPOSITION` в `spec-data.js`: из набора исключаются «Облицовка стен из гипсокартона/фанеры в два слоя по металлическому каркасу» и «Устройство утепления стен» (по 180 м², `unit: 'м2'`), взамен добавляется «Штукатурка стен толщиной до 20 мм по сетке», `vol: 'area*3'` (та же формула, что у исключённой облицовки), `wp`/`mp` взяты ровно из существующей поз. 43 (2347,25 + 138,36 = 2485,61 ≈ 2486 ₽/м², не придуманы заново). Применяется в `SpecCalc.compute` до цикла расчёта, только для `mode !== 'whitebox'` и не для `premium` — `whitebox` явно не тронут (раздел «Не трогать» ТЗ).
- `TIER_LABELS.cosmetic = 'Косметический'` добавлен (сам набор позиций для косметического — часть 4, не в этом отчёте).

**Коммит:** `8db0db2`. Обновление ТЗ с выбором коэффициентов (готовит следующий шаг) — `eef8bd4`.

**Проверено** (те же входные):
```
euro    -> 4 952 991 ₽ (82 550 ₽/м²), 50 позиций — точное совпадение с целью
capital -> 4 051 078 ₽ (67 518 ₽/м²), 49 позиций — точное совпадение с целью (50 − 2 исключённых + 1 добавленная)
premium -> не тронут: ветка isPremium исключает и смену состава, и любые новые множители по построению
```
`whitebox`/`capital` отдельно прогнан — 30 позиций (по факту, у whitebox исключаемые позиции и так были с `vol: '0'`), смена состава не применяется, как и требовалось.

## Часть 3.2 — понижающие коэффициенты капитального

**Было:** после смены состава (часть 3.1) `capital` уже давал 67 518 ₽/м² (+13,5% к верху вилки квиза) при всех множителях 1,0 — то есть целевой коридор 10–15% был закрыт одной сменой состава, без единого коэффициента.

**Стало:** добавлены понижающие — **мягкий вариант**, выбранный из трёх прогнанных владельцем (мягкий +9,9%, средний +7,9%, жёсткий +5,9% — два последних уходят ниже целевого коридора):
```js
prep:     { wp: 0.90, mp: 0.90 },   // 1 слой шпатлёвки вместо 2, без стеклохолста
finish:   { wp: 1.00, mp: 0.85 },   // финишный материал дешевле
terminal: { wp: 1.00, mp: 0.80 },   // оконечка эконом-сегмента
```
Остальные пять классов (`rough`, `engineering`, `sanitary`, `doors`, `windows`) остались единицами. `euro` и `premium` не тронуты.

**Коммит:** `2994469`.

**Проверено** (те же входные):
```
capital -> 3 920 667 ₽ (65 344 ₽/м²), 49 позиций
euro    -> 4 952 991 ₽ (82 550 ₽/м²), 50 позиций — не изменился
premium -> 41 033 273 ₽ (683 888 ₽/м²), 120 позиций — не изменился
```
Целевое значение из ТЗ — 65 345 ₽/м² (3 920 670 ₽). Фактическое расхождение — 1 ₽/м² и 3 ₽ в абсолютной сумме, в пределах явно оговорённого допуска «рубль-два округления» (накопление построчных `Math.round` на 49 позициях), не переигрывалось.

## Итоговая таблица по уровням

На входных 60 м² / 1 санузел / 3 окна / 2 комнаты, полный цикл, без перепланировки. Цифры детальной сметы перепроверены прогоном заново для этого отчёта, не переписаны из предыдущих сообщений.

| уровень | детальная смета | вилка квиза | к верху вилки |
|---|---|---|---|
| Капитальный | 3 920 667 ₽ (65 344 ₽/м²), 49 позиций | 37 853 — 59 483 ₽/м² | +9,9% |
| Евроремонт | 4 952 991 ₽ (82 550 ₽/м²), 50 позиций | 60 000 — 85 000 ₽/м² | −2,9%, внутри вилки |
| Премиум | 41 033 273 ₽ (683 888 ₽/м²), 120 позиций | 160 000 — 220 000 ₽/м² | +211% |

**Методологическая оговорка, важная для чтения таблицы.** Вилки в этой таблице получены по-разному, и это не случайность, а то, как были заданы исходные цифры:
- «Евроремонт» и «Премиум» — это сырые границы `TIERS.euro`/`TIERS.premium` из `calculator.js` (`baseLow`/`baseHigh`, без модификаторов площади/дома/etc.) — 60 000–85 000 и 160 000–220 000 ₽/м² соответственно. Проверено: `(82550/85000-1)*100 = −2,9%`, `(683888/220000-1)*100 = +210,9% ≈ +211%` — совпадает.
- «Капитальный» — это **не** сырые `TIERS.capital` (35 000–55 000 ₽/м², дал бы +18,8%, не +9,9%), а результат реального прогона `calculateB2C` с конкретными входными (60 м², новостройка, монолит, без отделки, без дизайн-проекта), которые дают модифицированную вилку 37 853–59 483 ₽/м² — та же цифра, что фигурирует в самом ТЗ как эталонная («Проблема», §1). Проверено: `(65344/59483-1)*100 = +9,9%` — совпадает.

Если в будущем понадобится единая методология сравнения (например, для косметического уровня в части 4), эту оговорку нужно будет разрешить явно, а не молча.

## Отдельные пункты

1. **Исходная задача закрыта.** Разрыв капитального с вилкой квиза был +39%, стал +9,9% — внутри целевого коридора 10–15% (даже чуть ниже верхней границы). Основную работу сделала смена состава сама по себе (+13,5%, часть 3.1); коэффициенты (часть 3.2) довели с +13,5% до +9,9%.
2. **Евроремонт лёг внутрь своей вилки без подгонки** — с него только сняли надбавки (`×1,30`/`×2,00` → `×1,00`), никакие позиции и расценки не трогались. −2,9% к верху вилки подтверждает, что `SPEC_DATA.full` действительно описывает евроремонт, а не что-то среднее.
3. **Премиум остаётся с превышением +211%** — известный, отдельный долг, не в этом ТЗ. Причина (по описанию задачи) — мебель, техника и декор внутри набора `SPEC_DATA.premium` учтены безусловно, а должны включаться опционально (галочкой), как в других калькуляторах.
4. **Критерий приёмки 5 из ТЗ выполнен частично, намеренно.** `TIER_LABELS.cosmetic === 'Косметический'` — сделано. Прямой маппинг `cosmetic → cosmetic` в `tierMap` (`src/data/specTier.js`) — отложен до части 4 по решению от 23.09.2026: набора позиций для косметического уровня ещё нет (`SPEC_DATA.cosmetic` не существует), прямой маппинг сейчас сработал бы через молчаливый фолбэк на `capital` внутри `SpecCalc.compute` — то есть визуально то же самое, но неявно, а не через понятный `tierMap`. Оставлено как `cosmetic: 'capital'` до появления реального набора.
5. **Часть 4 («Косметический») не выполнена.** Нужны от Дмитрия: расценки (`wp`/`mp`) на две новые позиции — «Заделка трещин» и «Демонтаж существующего покрытия пола», и решение по шпатлёвке в один слой (отдельная расценка или множитель к двухслойной). Реализуется отдельным заходом после получения этих данных.
