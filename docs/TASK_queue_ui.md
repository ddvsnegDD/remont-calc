# ТЗ: /club и /pro показывают все оплаченные периоды и позволяют продлевать (q24 + проблема очереди)

Решение Дмитрия 02.10.2026: вариант А. Кнопка оплаты есть у каждого тарифа всегда, страница показывает все оплаченные периоды списком. Основание: оферта п. 4.4 и текст над тарифами обещают «оплаченный период добавится к окончанию».

## Проблема

1. На /club у текущего тарифа вместо кнопки зелёная плашка «✓ до …» (src/pages/ClubPage.jsx, строки ~269-283 для «Месяц» и ~286-300 для «Год»). Продлить тот же тариф заранее нельзя, хотя сервер это умеет (`applySucceededPayment` ставит новый период в хвост).
2. Страница знает только подписку, действующую прямо сейчас: `getActiveSubscription` требует `started_at <= NOW()`, и именно её отдают `/api/auth/me` и `/api/subscription/status` (server.js, строки ~235-275). Оплаченный, но ещё не начавшийся период (очередь) на странице не виден. Живой случай 02.10 (аккаунт 58): месяц до 01.11.2026 действует, год до 01.11.2027 оплачен и стоит в очереди, а у карточки «Год» снова кнопка «Оплатить». Человек может заплатить второй раз.
3. На /pro при активном PRO кнопки продления нет (ProPage.jsx, строки ~72-80 и ~155-158): «✓ PRO уже активен».

## Что сделать

Работа в трёх частях. После каждой части: `npx vite build`, `node --check` для серверных файлов, один коммит, не пушить, остановиться и написать короткий отчёт в docs/REPORT_queue_ui.md (дописывать раздел на каждую часть).

### Часть 1. Сервер отдаёт очередь

1. server/db.js: новая функция `getSubscriptionQueue(userId)`:
   `SELECT plan, status, started_at, expires_at FROM subscriptions WHERE user_id = $1 AND status IN ('trial','active') AND expires_at > NOW() ORDER BY started_at ASC, id ASC`.
   Возвращает и текущую подписку, и будущие.
2. server.js: в ответы `/api/auth/me`, `/api/subscription/status` и `/api/auth/verify` добавить поле `queue`: массив `{ plan, status, tier, startedAt, expiresAt }` (tier через `tierOf`). Поле `subscription` и `hasAccess` остаются как есть, доступ по-прежнему определяет только текущая подписка.
3. Ничего не менять в `getActiveSubscription`, в выдаче и возвратах.

Критерий части: для аккаунта 58 `/api/subscription/status` возвращает две записи в `queue` (месяц с текущим started_at, год с будущим), а `subscription` только месяц.

### Часть 2. /club и страница возврата

1. src/lib/auth.jsx: хранить `queue` (по умолчанию `[]`), заполнять из `/api/auth/me`, `/api/subscription/status` и ответа verify, очищать при выходе, отдавать через контекст.
2. ClubPage.jsx, блок «Тарифы»:
   - Над карточками, если `queue` не пуст, список оплаченных периодов, по строке на период: «✓ {labelOf(plan)}: до {дата}» для уже идущего и «✓ {labelOf(plan)}: с {дата} до {дата}» для будущего. Триал показывать так же («Триал (14 дней): до …»). Даты формата `toLocaleDateString('ru-RU', { day: 'numeric', month: 'long', year: 'numeric' })`, как сейчас.
   - Обе карточки всегда показывают кнопку оплаты. Текст кнопки «Продлить», если в `queue` есть период этого плана (club_monthly или legacy monthly для карточки «Месяц»; club_yearly или legacy yearly для карточки «Год»), иначе «Оплатить». Зелёные плашки «✓ до …» вместо кнопки убрать.
   - Бейдж на карточке: «ТЕКУЩИЙ» на карточке плана, который идёт прямо сейчас (элемент очереди со startedAt <= сейчас), иначе «ВЫГОДНО» у года и без бейджа у месяца. Для триала бейдж «ТРИАЛ» убрать, триал виден в списке выше.
   - Если очередь не пуста, под кнопкой серым мелким текстом: «Новый период начнётся {дата последнего expiresAt в очереди}». Дата считается так же, как на сервере (максимум expiresAt по всем элементам очереди).
   - Тексты над тарифами не менять.
3. PaymentReturnPage.jsx, состояние succeeded: если у подписки платежа `startsAt` в будущем, строка «{label} с {startsAt} до {expiresAt}», иначе как сейчас «{label} до {expiresAt}». Сервер уже отдаёт `startsAt` в `/api/payments/:id` (server.js ~524).
4. Не менять поведение покупки Клуба при активном PRO: сервер ставит Клуб в хвост PRO, это сохраняется. В отчёте отметить, нужно ли на /club для PRO-пользователя особое сообщение (решит Дмитрий).

### Часть 3. /pro

1. ProPage.jsx: при `hasPro` в шапке рядом с зелёной плашкой «✓ PRO активен до …» показать кнопку «Продлить PRO за {PRO_PRICE} ₽» (вызывает `handlePay`), под ней серым: «Период добавится к окончанию, новый срок начнётся {дата последнего PRO в очереди}». Плашка использует последнюю дату окончания PRO из `queue`, не только текущего периода.
2. Кнопка в сравнении тарифов (строки ~155-158): при `hasPro` текст «Продлить PRO», не disabled, вызывает `handlePay`.
3. Текст про замену Клуба при оплате PRO («Если у вас действует Клуб, он заменяется на PRO…») оставить, он показывается при `!hasPro`.

## Что не трогать

- server/db.js: `applySucceededPayment`, `applyRefund`, `getActiveSubscription`; схему БД.
- Лимиты и доступ: проверки доступа везде по-прежнему идут по текущей подписке (`hasAccess`, `hasPro`).
- B2BCabinetPage.jsx, HomePage.jsx (показывают срок текущего периода): не менять, в отчёте перечислить места, где выводится `subscription.expiresAt`.
- Юридические тексты, FAQ.

## Критерии приёмки

1. `npx vite build` и `node --check server.js server/db.js` проходят.
2. Часть 1: для пользователя без подписок `queue` пустой массив; для пользователя с двумя периодами в `queue` две записи по порядку started_at; `subscription` не изменился.
3. Часть 2: у обеих карточек всегда есть кнопка; текст «Продлить» у плана, который уже есть в очереди; список периодов над карточками; серая строка про начало нового периода; на 390 px ничего не переполняется (проверить как раньше изолированным репро с реальным CSS).
4. Часть 3: у PRO-пользователя есть кнопка «Продлить PRO», у не-PRO всё как раньше.
5. Три коммита (по одному на часть), без push.
