## §2.1 `formatRub` падает на пустом значении

### Факты прогона

```
formatRub(undefined) → TypeError: Cannot read properties of undefined (reading 'toLocaleString')
formatRub(null)      → TypeError: Cannot read properties of null (reading 'toLocaleString')
formatRub(NaN)       → "не число ₽"
formatRub(Infinity)  → "Infinity млн ₽"
formatRub(1234567)   → "1,23 млн ₽"
```

Падение на `null` в отчёте Искры не упомянуто, а оно важнее: см. связку в §2.2.

Якорь: `export function formatRub(n)` в `src/lib/calculator.js`.

### Что сделать

В начало функции добавить:

```js
if (!Number.isFinite(n)) return '—';
```

Это закрывает `undefined`, `null`, `NaN` и обе бесконечности одной строкой. Строку `'не число ₽'` из текущей ветки убрать, она теперь недостижима.

Отдельно: найти по `grep -rn "rpkm-last-b2c\|sessionStorage.getItem" src/` все чтения результатов расчёта из `sessionStorage` и обернуть `JSON.parse` в `try/catch`. Испорченное или устаревшее содержимое хранилища не должно ронять страницу результата.

## §2.2 Мусор на входе даёт смету из ничего и отрицательные деньги

### Факты прогона

Детальная смета, `SpecCalc.compute`, при санузлах 1, окнах 4, комнатах 2, тир «капитальный»:

| Площадь на входе | Что взял калькулятор | Итог |
|---|---|---|
| `0` | 1 м² | 1 526 890 ₽ |
| `-50` | 1 м² | 1 526 890 ₽ |
| `NaN` | 1 м² | 1 526 890 ₽ |
| `'abc'` | 1 м² | 1 526 890 ₽ |
| `undefined` | 1 м² | 1 526 890 ₽ |
| `1e9` | 1 000 000 000 м² | 59 205 442 802 238 ₽ |

Полтора миллиона рублей на один квадратный метр получается потому, что часть позиций не зависит от площади и считается комплектом.

Квиз, `calculateB2C`, те же входные:

| Площадь на входе | `totalLow` |
|---|---|
| `0` | 2 271 180 ₽ (молча подставлено 60 м²) |
| `'abc'` | 2 271 180 ₽ |
| `undefined` | 2 271 180 ₽ |
| `-50` | **−2 163 000 ₽** |
| `1e9` | 36 050 000 000 000 ₽ |

Якоря: `Math.max(1, parseFloat(area) || 0)` в `src/lib/spec-calculator.js`, `parseFloat(answers.area) || 60` в `src/lib/calculator.js`.

**Связка с §2.1, которой нет в отчёте.** `calculateB2B` при `bathrooms: 'abc'` возвращает не NaN, как утверждал аудит, а `null` во всех денежных полях: `lowPerM2: null, highPerM2: null, totalLow: null, totalHigh: null`. Дальше `null` попадает в `formatRub`, та бросает `TypeError`, и страница результата умирает белым экраном. То есть §2.1 и §2.2 это не два независимых мелких дефекта, а одна цепочка от мусора на входе до упавшего интерфейса.

Якорь: `parseInt(answers.bathrooms || 1)` в `src/lib/calculator.js`.

### Что сделать

**Единый валидатор.** Завести в `src/lib/calculator.js` и экспортировать:

```js
export function validateNumber(v, { min, max, name }) {
  const n = typeof v === 'number' ? v : parseFloat(String(v ?? '').replace(',', '.'));
  if (!Number.isFinite(n)) return { ok: false, error: `${name}: введите число` };
  if (min != null && n < min) return { ok: false, error: `${name}: не меньше ${min}` };
  if (max != null && n > max) return { ok: false, error: `${name}: не больше ${max}` };
  return { ok: true, value: n };
}
```

Запятая как разделитель обрабатывается намеренно: русскоязычный пользователь напишет «62,5».

**Принцип, важнее конкретных границ.** На невалидном входе расчёт не запускается и в интерфейсе появляется сообщение. Молчаливая подстановка дефолта запрещена: пользователь не должен получить цифру, которую он не заказывал. Сейчас `|| 60` и `Math.max(1, ...)` делают ровно это.

**Границы. Решение владельца от 22.09.2026.** Верхних границ для офисных калькуляторов не ставим, офисы бывают любого размера. Правило: число должно быть конечным и строго больше нуля. Ноль, отрицательные значения и нечисловой мусор отвергаются с сообщением в интерфейсе. Верхняя граница остаётся только там, где уже есть, в квизе B2C (`min:20, max:250`, якорь `type:'area'` в `src/pages/B2CQuizPage.jsx`). Для счётных полей (санузлы, окна, комнаты, рабочие места, переговорные) правило то же: целое, конечное, не меньше нуля.

**Где подключить.** По каждому месту: показать ошибку в интерфейсе рядом с полем, расчёт не запускать.

- `src/lib/calculator.js`, `calculateB2C` — площадь, комнаты, санузлы;
- `src/lib/calculator.js`, `calculateB2B` — площадь, `bathrooms`, `workplaces`, `meetingRooms`;
- `src/lib/spec-calculator.js`, `SpecCalc.compute` — площадь, санузлы, окна, комнаты;
- `src/lib/office-calculator.js` — площадь и все счётные поля;
- компоненты ввода: `B2CQuizPage.jsx`, `B2CDetailPage.jsx`, `B2BQuizPage.jsx`, `B2BOfficePage.jsx`, `B2BOfficeDetailPage.jsx`.

Расчётные функции при невалидном входе должны возвращать `{ ok: false, error }`, а не бросать исключение и не считать по дефолту.

## §2.3 Порядок начисления перепланировки

### Что подтверждено

Находка верна, но механика не та, что описана в отчёте. В `src/lib/spec-calculator.js` уже есть разделение на две сущности:

```js
const REPLAN_SURCHARGE = {
  no:    { fixed: 0,     pct: 0,    perM2: 0,   perRoom: 0 },
  light: { fixed: 80000, pct: 0,    perM2: 0,   perRoom: 0 },
  full:  { fixed: 80000, pct: 0.05, perM2: 500, perRoom: 15000 },
};
```

`approvalCost = fixed + perM2 × площадь + perRoom × (комнат − 1)` это согласование в МЖИ, `worksCost = grandTotal × pct` это работы по перепланировке.

Дефект один: `worksCost` берётся от суммы, в которую уже добавлен премиальный резерв 5%. Прогон на премиуме 60 м², 2 комнаты: двойной счёт составляет **100 119 ₽**. В отчёте Искры указано 118 866 ₽, цифра завышена.

### Решение владельца

Порядок **оставить как есть**. Зафиксировать константой с комментарием, чтобы в будущем никто не «починил» молча:

```js
// Надбавка за перепланировку считается от суммы, включающей премиальный резерв.
// Это осознанное решение владельца от 18.09.2026, а не недосмотр.
// Двойной счёт (5% от 5%) на премиуме 60 м² составляет ~100 000 ₽ и принят.
const RESERVE_BEFORE_REPLAN = true;
```

Синхронизировать описание в `РЕЗЮМЕ-ПРОЕКТА.md`, где порядок описан иначе.

### Свести квиз к модели детальной сметы

Квиз считает перепланировку другим способом: `REPLAN_MOD` множит **весь итог** на 1,03 для лёгкой и 1,16 для полной (якорь `export const REPLAN_MOD` в `src/lib/calculator.js`). На одних и тех же входных капитальный ремонт 60 м² даёт 5 013 104 ₽, и квиз накидывает за полную перепланировку около 800 000 ₽, а детальная смета 375 655 ₽, из которых 125 000 согласование и 250 655 работы. Расхождение вдвое на один и тот же вопрос.

Решение владельца: квиз привести к модели детальной сметы. Множитель `REPLAN_MOD` заменить на ту же надбавку «фиксированная сумма плюс процент», выдаваемую вилкой, а не точной цифрой. Границы вилки сохранить теми же, какими они получаются сейчас из `lowPerM2`/`highPerM2`.

## §2.10 Экранирование в печатных отчётах

### Что проверено и что оказалось неверным

Функция `esc()` существует в обоих файлах и применяется к большинству подстановок, включая заголовок страницы: `<title>${esc(title)} — РПКМ</title>`, причём у всех четырёх генераторов заголовок имеет запасное значение. **Утверждение отчёта про `<title>Смета — undefined</title>` не подтвердилось.** Функций `buildSpecHTML`, `buildEstimateHTML`, `buildChecklistHTML`, на которые ссылается отчёт, в коде нет вовсе: экспортируются `generateB2CSummaryReportHTML`, `generateB2CDetailReportHTML`, `generateB2BReportHTML`, `generateB2BOfficeReportHTML` и `generateReportHTML`.

Реально не экранированы два места.

**Фотография в акте приёмки.** `src/lib/checklistReport.js`, якорь `<img src="${p.photo}"`. Значение приходит из `localStorage` без проверки. Кавычка в нём разрывает атрибут и позволяет дописать произвольные атрибуты тега.

Про серьёзность честно: наполняет это хранилище сам пользователь на своём же устройстве, поэтому пострадать он может только от себя. Это скорее дефект корректности, чем дыра в безопасности. Чинить всё равно стоит, потому что стоит одну строку, а при будущей синхронизации чек-листов между устройствами риск станет настоящим.

**Иконки групп.** `src/lib/estimateReport.js`, четыре места, якоря `${g.icon || ''}` и `${sec.icon || ''}`. Сейчас там захардкоженные эмодзи из файлов данных, риска нет. Экранировать на будущее.

### Что сделать

Для фото:

```js
const safePhoto = typeof p.photo === 'string' && p.photo.startsWith('data:image/') ? p.photo : '';
```
и подставлять `safePhoto`, пустое значение означает пропуск тега `<img>` целиком.

Для иконок: обернуть в существующую `esc()`.

## Критерии приёмки

1. §2.4 либо воспроизведён и починен (прогон до и после показывает исчезновение скачка на границе `S1`), либо задокументирован как невоспроизводимый с приложенным выводом.
2. `formatRub(undefined)`, `formatRub(null)`, `formatRub(NaN)`, `formatRub(Infinity)` возвращают `'—'` и не бросают исключений.

6. Константа `RESERVE_BEFORE_REPLAN` присутствует с комментарием, описание в `РЕЗЮМЕ-ПРОЕКТА.md` ей соответствует.

9. `npx vite build` проходит.
